# rs-scene-render

A deterministic, GPU-accelerated renderer for scene-render 1.1 documents: it validates an XML scene description, evaluates it frame by frame, composites it in linear light with wgpu, and encodes and delivers finished video, audio and stills. The command-line tool is `scene-render`.

Linux x86-64 binaries and SHA-256 checksums are available on [GitHub Releases](https://github.com/pedroanisio/rs-scene-render/releases). See each release's notes for runtime requirements. Pushing a `v` tag matching the Cargo workspace version runs the complete CI suite before building, smoke-testing and publishing the binary through the release workflow.

A scene-render 1.1 document either loads into a typed, fully resolved Rust model or fails with every problem it contains, each carrying a stable code, a line and column, an element path and, where one exists, a fix. Every other crate reads only this model, so the renderer never sees an unvalidated attribute.

Rust 1.90 or newer is required; CI checks the complete workspace on 1.90.

```
cargo build --release
target/release/scene-render validate promo.scene.xml
target/release/scene-render inspect promo.scene.xml
target/release/scene-render eval promo.scene.xml --time 2.5 --variant dark --param headline=Hi
target/release/scene-render eval promo.scene.xml --bench
target/release/scene-render render promo.scene.xml --time 2.5 -o frame.png
target/release/scene-render render promo.scene.xml --frames 0..250 -o out/frame_%04d.png
target/release/scene-render encode promo.scene.xml                       # every <output>
target/release/scene-render encode promo.scene.xml -o preview.mp4 --representation proxy
target/release/scene-render resolve promo.scene.xml                      # make generated media and captions
target/release/scene-render explain C21
```

### Premium production acceptance

`tools/production_gate.py` checks an exact final narrated candidate and its review evidence. Encoding should use `--strict --no-upload --quality final --json`; save stdout as the delivery report. `frames REPORT` checks the decoded frame count, dimensions and frame rate, including fractional-duration endings. `technical` requires the project, `--scene`, `--video`, `--engine`, `--encode-report`, `--tools-dir` (the production audio tools), `--voice-end` (last word in encoded-video seconds), and one or more `--captions` VTT/SRT files. It runs validation, asset resolution, audio checks including the encoded ending, final decoded loudness/true-peak analysis and black/freeze detection, and checks caption timelines, line lengths and the 17-character-per-second limit.

After technical success, `init PROJECT` creates `qa/PREMIUM.json` with unassessed scores. `check PROJECT` requires an independent final audiovisual review, eight QA reports including `EDITORIAL.md`, ten fixed categories (each ≥8.5; Visual quality and Cinematography ≥9.0; unrounded mean ≥9.0), thirteen role assignments or explicit nonapplicability, runtime sampling and accepted fixes with regression evidence. Art must identify the approved signature still from before the encode, the channel's reference board and a visible advance; each category must name a professional comparison. Hashes bind sources, assets, engine, final video, captions and evidence; changing them invalidates acceptance. Direct listening and playback attestations must come from a reviewer capable of performing them. Automated probes and artistic reference clips alone cannot establish premium quality. Gate success never authorizes an upload or publication.

The production handbook defines rollout: newly started films use this contract; approved films and the existing grandfathered batch retain their original acceptance standard. Simulation scenes remain serial until a parallel implementation matches serial reference frames, including late settled states.

## Document model

### The contract is generated from the schema

`crates/sr-model/build.rs` reads `schema/scene-render-1.1.xsd` and `schema/scene-render-1.1.sch` at build time and emits three files, so a schema change reaches the validator and the model in the same build:

- **Schema tables** — all simple types with their facets and all complex types with attribute declarations and content particles. `xsd::structure` interprets them.
- **Typed model** (~20,000 lines) — 134 enums for the enumerations, 18 checked newtypes for the numeric restrictions (`UnitDecimal::new(1.5)` fails), one struct per complex type with defaults applied, and shared enums for the model groups (`Node`, `Animation`, `NodeBehaviour`, `BodyBehaviour`).
- **Assert catalogue** — id, context, test and message of all 140 Schematron asserts, used by `scene-render explain`.

The generator accepts exactly the XSD subset the schema uses and aborts the build on anything else, so an unsupported construct cannot be ignored silently.

### The schema is vendored from sr-core

The canonical copy of the schema lives in [sr-core](https://github.com/pedroanisio/sr-core) (`schema/scene-render.xsd` and `.sch`), shared by every scene-render engine. This repository vendors a released version unchanged under its own file names and records the tag and SHA-256 of each file in `schema/UPSTREAM` (currently schema 1.1.3). The schema changes only through an accepted Scene Render Enhancement Proposal (SREP) in sr-core; this engine is the reference implementation an SREP needs before review, and takes the released files once it is accepted.

On top of 1.1.3, the vendored files carry the additions SREPs 9 to 11 and 13 (in review) propose for schema 1.2, implemented here as their reference: map tiles and basemaps, draped map ground and globes, rigid bodies on `object3D`, and segments of the composition played by an output. Documents that use the new elements or asset kinds (`<tiles>`, `<basemap>`, `object3D/rigidBody`) declare `version="1.2"`, which rule V5 enforces; the new attributes and enumeration values are accepted in every version. When sr-core releases 1.2.0, its files replace these.

### Loading runs four stages over one parse

| Stage | Module | Codes | What it enforces |
|---|---|---|---|
| Structure | `xsd::structure`, `xsd::simple` | `S01`–`S12`, `W01` | Content models, attribute declarations, lexical forms, enumerations, bounds, patterns, `xs:ID` uniqueness, `xs:IDREF` resolution |
| Rules | `rules` | `V1`–`V7`, `C1`–`C59`, `R1`–`R41` (with the `R24-*`, `R25-*`, `R30-*` and `R31-*` families), `P01`–`P05` | The 56 Schematron patterns, including the version gates, and the limits a renderer needs: soft-body stiffness, counts that multiply into nodes or particles, symbols that contain themselves, expression nesting and cyclic matte dependencies |
| Assets | `assets` | `A01`–`A07` | Existence of every input URI, SHA-256 of every `@sha256`/`@cacheSha256` (generated media, transcriptions, physics caches), every frame of every image sequence, declared image dimensions against readable local image headers |
| Model | `model`, `document` | `M01` | Typed construction and the ID index |

Structure and rules always both run, so one pass reports every problem. The model is built only when no stage reported an error. `Document` then resolves ids by kind (`doc.asset("logo")`, `doc.paint("sunset")`, `doc.node("title-layer")`), style tokens (`doc.resolve_color`, `doc.resolve_paint`) and the timeline (`doc.fps()`, `doc.frame_count()`); `values` supplies lengths with units, colours, rational frame rates, drop-frame timecodes, points, aspect ratios and digests.

`A07` warns when an `<image>` asset's declared `width`/`height` differs from its local source file. Layout still uses the declared size; a different aspect ratio distorts the image. Dimensions include EXIF orientation, matching the upright decoded image. Use the file's dimensions on the asset and `boxWidth`, `boxHeight` and `fit` on the layer to place it. The probe reads image headers once per source file without decoding pixels; it skips remote sources, proxy representations and formats without a native header reader. `--no-assets` skips it and `--deny-warnings` makes it fail validation.

### Conformance is measured against lxml

`tools/oracle.py` validates with libxml2's XSD validator and ISO Schematron on libxslt, the engines the schema names. Two results follow from it:

- **Corpus** — `tools/build_corpus.py` writes 179 documents into `tests/corpus`: a kitchen-sink document that exercises every section, one mutation per Schematron assert (all 140 ids, including every paint and colour attribute of the `R24`, `R25`, `R30` and `R31` families), one per structural and asset code, and the oracle's verdict for each. `cargo test` requires the Rust validator to produce exactly the manifest's codes for every document.
- **Differential fuzzing** — `tools/oracle_diff.py COUNT SEED` mutates the kitchen sink at random and compares the XSD verdict and the multiset of (assert id, line) pairs. Seeds 1–4 (7,000 mutants, about 5,300 failed asserts) produce zero disagreements.

sr-model is stricter than libxml2 in three places, each required by XSD 1.0: it resolves `xs:IDREF` values (`S10`), rejects whitespace-only `xs:IDREFS`, and rejects `1e` as an `xs:double`. XPath `number()` follows libxml2, which parses exponent forms (`2.4e1` compares as 24), because the Schematron file names libxslt as its engine.

A 10,000-node composition (40,000 elements, 2.1 MiB) parses, validates and loads in about 100 ms in a release build. `crates/sr-model/tests/perf.rs` asserts a 200 ms budget and `cargo run --release --example stages -- FILE` times each stage.

## Evaluation

`sr-eval` compiles a validated document once per variant and layout, then evaluates any frame as a pure function of time: `Evaluator::evaluate(t) → FrameGraph`. A FrameGraph lists the active nodes in paint order (containers before children, children by `z`) with local and world transforms, own and accumulated opacity, timeline, local and source times, resolved text, matte links, the current value of every animated property, active transitions with eased progress, the active camera, and the animated state of paints, effects, lights and other elements outside the composition. The same `(document, options, t)` gives the same bits on every machine, in any evaluation order.

**Templating runs once.** Parameter values come from `@default`, then the variant's `set`, then a data row (`--row`), then `--param`, and are checked against type, `min`/`max`, `maxLength`, `pattern`, `options` and `required`. Binds (with `map`), variant overrides and layout overrides then change attributes by id through a generated name-based `Element` interface on every model type. `{{id}}` and `{{item.field}}` placeholders resolve in text-bearing attributes; per-copy placeholders resolve on each repeat copy. Repeats expand into scoped copies (`list[2]/label`) with cumulative offsets, rotation, scale, opacity and a start stagger; instances clone their symbol with ids scoped as `instance/inner`, apply their overrides inside that scope, and run on the symbol's own clock; includes load another document, namespace its assets (`inc/logo`) and follow the same clock rules. Self-instantiation is rejected.

**Timing** places every node before the first frame: `start`/`end` and `startMarker`/`endMarker`, sequence placement with `timeGap`, auto-transitions at junctions, explicit transitions with handle extension, group `timeOffset`/`timeScale`, repeat stagger, and the media clock of layers and instances (`speed`, `timeStretch`, `clipIn`/`clipOut`, `reverse`, `loop`, `freezeAt`, `timeRemap`). Layers of videos and image sequences end with their media unless `@end` says otherwise; `freezeAt` holds the frame at that layer time for the layer's whole window, so a frozen layer does not end with its media.

**Paint order** is static `z` among siblings, sorted once at compile time (stably, in document order for equal values). `object3D` and `camera` nodes are exempt: their `z` is a depth in scene units, so they keep document order. A node whose `z` is animated (keys, an expression or a link) marks its siblings for restacking: each frame the evaluator sorts them by the current value, stably in document order, and other sibling lists keep their compiled order at no cost. `z` is an integer property, so an animated value rounds, as `eval` reports it.

**Layout is part of evaluation.** Before any pixel exists, `sr-eval` gives every node a box: fit boxes or the asset's size for layers, `width`/`height` for shapes and groups, the symbol box for instances. Fit places media in the box (`contain`, `cover` with `focusX`/`focusY`, `fill`, `scale-down`, `contain-blur` with a blurred cover fill behind) after crops and flips. Image layers are sampled bilinearly where magnified and trilinearly (mip-mapped) where minified; `resample="bicubic"` (Catmull-Rom) or `"mitchell"` (Mitchell–Netravali, B = C = ⅓) swaps the magnified filter for a nine-fetch cubic clamped to the range of the four nearest texels, and leaves minified samples alone. Groups with `layout` arrange their children as rows, columns, stacks or grids with gap, padding, all six `justify` modes and `alignItems` including `stretch`; a child's own `x`/`y` offset it from its slot. `alignX`/`alignY` pin any node to its parent box, the frame or the safe area, whose insets come from `safeArea` attributes over a preset table (EBU R 95 action and title safe, and the vertical social formats). Selecting a layout changes the frame size and safe area, and the same rules re-flow the scene (`reframe="reflow"`, the default). With `crop`, `fit` or `fit-blur` the composition renders at the project size instead, and delivery places it in the layout's frame: scaled to cover and cropped, with `focusX`/`focusY` sharing out the part cut away; scaled to fit, centred (the bars are transparent, black in an opaque output; `project@background` colours the composition's own frame only); or scaled to fit over a copy of itself scaled to cover and blurred (the frame averaged in 8 × 8 blocks, then a separable Gaussian of σ = 3 blocks), with the focus placing both.

**Safe areas are checked, not only used for placement.** `safeArea@enforce="warn"` or `"error"` holds text layers, burned captions and nodes tagged `cta` or `logo` inside the region the safe area leaves, at every frame validated or rendered: a crossing is diagnostic `SA01`, a warning for `warn`, an error for `error` that makes `validate` exit 1 and stops `render` and `encode` before a frame is written. Nodes and text layers are measured by their layout box through their world transform (set the box to the text, since the box and not the glyph ink is what is held to the region); burned captions are measured by their laid-out glyphs; a caption track checks against the safe area it names with `@safeArea`, else the project's; hidden nodes (opacity 0) and sidecar tracks are not checked; `validate` and `encode` audit every frame of a short range and, on a long one, the window edges and key times of the checked nodes and caption pages plus a coarse grid (at most 240 frames, evaluated without simulations), and say `sampled N of M frames` when they did not look at every frame. `safeAreaForce="true"` on a node, an instance or a symbol exempts it and everything it contains from the check, for a deliberate placement outside the region (the brand notch at the frame edge); `validate` prints one `info[SA02]: <id> forced outside the safe area` line for every node that carries it, so a force never hides, and the line neither fails `--deny-warnings` nor changes the exit code. `validate` also reports the errors compiling the document for rendering would raise (an animated key that does not parse as its property's type, an expression with an unknown function or a property the element lacks), so a document it accepts is one `render` can compile. The presets (`youtube-shorts`, `tiktok`, `instagram-reels` and the others) are approximations with no platform source, and the measured placement of a platform's interface differs from them; for a production setting declare a custom `safeArea` with explicit `top`, `right`, `bottom` and `left` fractions (for a 1080 × 1920 frame, x 80–920 and y 220–1420 is `left="0.0741" right="0.1481" top="0.1146" bottom="0.2604"`) and set `enforce` on that.

**Anchors use the node's local layout coordinates.** On a fitted layer, `anchorX` and `anchorY` refer to the fit box, not the source image's pixels. For a 1920 × 1080 box, use `anchorX="960" anchorY="540"`; setting `x="960" y="540"` places that anchor at the frame centre and keeps it there while the layer scales (before parent transforms). Different anchor positions and partial frame coverage are valid compositions.

**Animation** covers all 41 curves of `curveType`: holds and steps, CSS eases, `cubic-bezier` from `@bezier` or After Effects influence/speed handles, the 30 Penner curves, non-uniform Catmull-Rom and Kochanek–Bartels splines through neighbouring keys, and springs, the step response of a damped oscillator released at the segment's start key over the segment's duration: an under-damped spring that has not settled by the next key is blended linearly onto it, so the value lands exactly on that key and arrives with the spring's remaining speed (a fast tail), not as a position snap. A key's `interpolation` governs the segment from that key to the next key; for example, `interpolation="hold"` retains that key's value until the next key's time. The `back-*` curves take their overshoot from the leaving key's `overshoot` (default 1.70158, about 10 %; 0 is the plain cubic) and the `elastic-*` curves their ringing from its `period` (a fraction of the segment, default 0.3); either attribute on a segment whose curve does not read it is reported as E19. Channels support the five extrapolation modes, `loopIn`/`loopOut`, additive layering, the three time bases, marker-snapped keys, roving keys retimed for constant speed, and spatial Bézier tangents with arc-length parameterisation. Values keep their XSD kind: lengths keep units, colours resolve style tokens, and results clamp to the attribute's facet range, so an overshooting `back-out` cannot push `opacity` past 1. Motion paths accept full SVG path data (arcs included) with constant-speed sampling and auto-orientation; links map another property, a parameter, an audio envelope or a marker through scale, offset, clamp, delay and smoothing.

**Expressions** use a purpose-built parser for a side-effect-free ECMAScript subset (declarations, `if`/`else`, `return`, the full operator set, arrays with subscripts, member access; no loops or function definitions, so cost is bounded by length). Assigning a name that is not declared declares it, and a subscript outside an array is `undefined`. Programs compile once to register bytecode. `prop("id.property")` resolves at compile time to a slot and a dependency edge; slots are evaluated in topological order and cycles are rejected with the cycle spelled out. Built-ins follow the schema list, including seeded `random`, `noise` and `wiggle`, `valueAtTime`, `loopIn`/`loopOut`, `spring`, `audioAmplitude` and `beat` (read from an `Analysis` table the media pipeline fills, see [media and delivery](#media-and-delivery)), and `markerTime` with generated `beat.N`/`bar.N`.

**Seeded randomness** is counter-based, so a draw depends only on its address and never on evaluation order. The lattice hash of seed, channel and index i is splitmix64(seed ⊕ splitmix64(channel ⊕ splitmix64(i))), with integers entering as two's-complement 64-bit values; its top 53 bits are a uniform value in [0, 1). `noise(x)` is 1D Perlin gradient noise whose lattice gradients come from that hash on channel 7 (fractal sums add octaves). `wiggle` sums octaves k on channel property·1024 + k, where the property's position in x, y, rotation, scaleX, scaleY, anchorX, anchorY, opacity gives its number, and other properties get 8 + the CRC-32 of their name; component c of an array adds c·2¹⁶. `random()` is the top 53 bits of the hash with seed, frame and call site + property·2³² (+ component·2⁴⁸). `noise` with a y or z is improved Perlin noise over a permutation of the hash's draws. The seed is the expression's `@seed`, else the project's. Supporting rules used by every seeded feature:
- lattice positions pack as `i | j << 21 | k << 42` (21 bits each, two's complement);
- normal draws are Box–Muller from one hash, u1 = (high 32 bits + ½) / 2³² and u2 = low 32 bits / 2³²;
- permutations are Fisher–Yates over the draws U(seed, channel, k), swapping i with ⌊u · (i + 1)⌋ for i = n − 1 down to 1;
- per-element seeds are the CRC-32 (IEEE) of the text "project seed:id:@seed:purpose" (text-animator order, wiggly selectors, scramble letters, effects);
- camera shake takes the four fractal noise values on channels 0 to 3 at `frequency` · t.

Every transcendental function comes from `libm`, so results are bit-identical across platforms.

Evaluation errors use codes `E01`–`E16` (expression compile errors, unknown properties with suggestions, dependency cycles, key parse errors, override and parameter errors, data sources, include failures, recursion, invalid links and paths) `E17` (a missing or malformed tracking file) and `E18` (a composition that expands into more than 2^19 nodes); `scene-render explain E03` describes each one.

**Performance scenario.** `crates/sr-eval/tests/perf.rs` evaluates 5,000 keyframed properties across 1,020 nodes plus 500 expressions into a full FrameGraph and asserts a 2 ms budget per frame on one core (release build); the median is 0.97 ms. `scene-render eval FILE --bench` measures any document.

**Limitations.**
- Animated elements of included documents outside their composition are not evaluated.

## GPU compositor

`sr-gpu` renders a FrameGraph into an RGBA16F texture in the working colour space with wgpu, headless, on Vulkan, Metal, DirectX 12 or OpenGL: `Renderer::render(&graph, program) → Frame`. Frames stay on the GPU; `read` copies one back and `to_srgb8` converts it for display. Everything a frame needs is planned on the CPU into one draw list per render target and submitted as a single command buffer.

**Compositing is isolated only where the result depends on it.** Instances, includes and groups that are isolated, clipped, masked, matted, carry effects or blend with a non-normal mode render their children into an offscreen, which composites as one layer; other groups pass their children straight through, with opacity multiplied down, so 2.5D children share the frame's camera space. Offscreens of sized nodes live in the node's own space, so moving, rotating or fading the node reuses the texture.

**Blend modes follow published definitions.** All 35 modes of `blendType` are implemented: the W3C Compositing and Blending formulas for the separable and non-separable modes, After Effects definitions for add, subtract, divide, the colour comparisons, linear/vivid/pin light, hard mix, dissolve, the stencil and silhouette modes, alpha add and behind. The non-separable modes and darker/lighter colour weigh luminance 0.3 R + 0.59 G + 0.11 B, and every mode but add, multiply and difference takes its inputs clamped to [0, 1]. As in After Effects, the composition composites on transparency and the project background goes beneath everything last, with a fixed-function destination-over draw, so `behind`, `subtract`, the stencils and silhouettes act on the layers only. A blend mode on a layer with nothing beneath it in the composition blends with transparency, so over the project background it looks like `normal`; put a layer (a full-frame rectangle) under it to blend with a colour. Dissolve keeps a pixel when a hash of its frame position and the project seed is below the layer's alpha: h = seed ⊕ x · 0x9E3779B97F4A7C15 ⊕ y · 0xC2B2AE3D27D4EB4F, finalised with MurmurHash3's 64-bit finaliser, top 24 bits over 2²⁴. Normal and dissolve use fixed-function premultiplied over; the other modes copy the backdrop under the layer's bounds and composite in the shader, and the stencil modes cover the whole target because they cut away everything outside the layer. A test checks every mode against a CPU reference to within f16 precision.

**Masks, mattes and edges are analytic.** Rectangles, ellipses and rounded rectangles are signed distance fields; polygons, stars and SVG paths (flattened to within ¼ px) use winding or even-odd coverage with distance to the nearest edge. Polygon and star vertices lie on the ellipse inscribed in the mask's box, from the top, clockwise, a star's inner ones on that ellipse scaled by `innerRadius` (a fraction, 0.5 when absent). Feather is a Gaussian blur of standard deviation `feather`: rectangles, rounded rectangles and ellipses integrate the blurred outline row by row (exactly for rectangles), polygons and paths take the normal distribution of their signed distance, exact along straight edges. Feather, expansion, invert, opacity and the seven combine modes (`add` is a + m − a·m) apply in local space, so masks stay sharp under any transform. Alpha, inverted alpha, luma and inverted luma mattes sample a matte texture rendered in the target's space. Layer edges are antialiased from their distance to the content rectangle rather than by multisampling.

**Colour is managed end to end.** The working space comes from `colorManagement/@workingSpace` or `project/@workingColorSpace`, from sRGB to ACEScg; primaries convert through XYZ D65 with Bradford adaptation for the DCI and ACES whites. Images decode through their asset `colorSpace`, `transfer` (sRGB, BT.1886, gamma 2.2/2.6, PQ, HLG, ACEScc, ACEScct) and `alpha`, into premultiplied working-space values with a full mip chain. `linearLight="false"` composites on encoded values, as After Effects does. Colour literals are working-space values in that space's own encoding.

**Paints and generators are procedural.** Linear, radial (focal point, focal radius, aspect), conic and mesh gradients evaluate per pixel with pad, reflect and repeat spread, stop midpoints, optional dither and interpolation in linear, sRGB, Oklab or OKLCh (shorter-hue). `rotation` turns a gradient about the centre of the painted box in pixels, whatever its units, radial `aspect` stretches x, and a mesh gradient is a Catmull-Rom surface through its grid for positions and colours alike (so a 2 × 2 mesh is bilinear in position), a missing point taking the nearest defined colour; patterns tile an image with offset, rotation and scale. Stops and gradient attributes animate through the FrameGraph. The ten generator kinds (solid, gradient, noise, fractal noise, Worley cells, checkerboard, grid, stripes, film grain, light rays) render on the GPU from their seeded, animatable parameters, mixing paint2 to paint in display sRGB. The noise kinds use improved Perlin noise with evolution as the third axis, octaves at lacunarity 2 and gain ½, jittered Worley cells, per-frame grain of three averaged draws and rays from an fBm over the angle, all over the seeded draws described under [evaluation](#evaluation): a Fisher–Yates permutation and U(seed, k, pack(i, j)) lattices, with the seed the CRC-32 of the project seed, asset id and `@seed`. The GPU computes the 64-bit hashes exactly with 32-bit halves. Checkerboard, grid and stripes centre their pattern on the asset, turn it clockwise by `angle` and scroll it by `evolution` periods: checker squares of `scale` with `paint` at the centre's, grid lines of about 4 % of `scale` (at least 1 px; `lineWidth` sets them in pixels, whatever the scale) starting at each multiple, stripes of period 2 × `scale` with `paint` first; the gradient kind mixes its paints premultiplied in sRGB encoding.

**2.5D.** Layers with `threeD` place their quad at `zDepth`, rotate it about the anchor by `rotationX` then `rotationY` (positive `rotationX` turns the top edge away from the viewer, positive `rotationY` the right edge, as in After Effects) and project it through a perspective camera centred on the frame, with the active camera's `fov` (60° horizontal by default); texture coordinates interpolate perspective-correctly. Consecutive 3D siblings draw back to front. Layers project through the active camera's position and rotation, so they stay registered with 3D objects when the camera moves, and a layer behind the camera is clipped rather than magnified.

**Nothing unchanged is drawn twice.** Offscreens and mattes are keyed by a hash of their content: node state relative to the target, source time for time-dependent assets, and animated paint and generator values. An unchanged subtree reuses last frame's texture. At the root, the longest run of leading draws that did not change between the last two frames is stored as a snapshot; the next frame restores it with one copy and draws only what follows, so static layers cost one texture copy after the second frame (the project background, drawn last, is one more quad). A test checks that restored frames are bit-identical to fresh renders.

**Golden frames.** `sr_gpu::golden` compares frames by PSNR and CIEDE2000 (verified against the Sharma–Wu–Dalal test data); a frame passes at PSNR ≥ 50 dB and maximum ΔE2000 ≤ 1. `crates/sr-gpu/tests/golden.rs` renders a scene that combines the compositor's features at three times and compares it with `tests/golden/kitchen_*.png`; `SR_BLESS=1` explicitly creates or rewrites them locally, after visual review. Missing references and dimension mismatches fail; blessing is forbidden in CI. Every comparison writes actual, expected, ×16 difference PNGs and metrics with the adapter description to `target/golden-output/` (override with `SR_GOLDEN_OUT`). The goldens use llvmpipe (Mesa lavapipe); see [reference provenance](crates/sr-gpu/tests/golden/provenance.json).

**Unsupported content is reported, not fatal.** Content the compositor cannot draw as authored is listed in `RenderStats::unsupported` and by the CLI (see [CLI](#cli)).

**Performance scenario.** `tools/perf_layers.py DIR` writes a scene of 200 image layers at 1920×1080, each rotated, moved and scaled, masked by a feathered ellipse, cycling through the 33 layer-local blend modes, all animated so no cache applies. `scene-render render DIR/perf_layers.scene.xml --bench --frames 0..60` reports median and p95 frame time and the CPU share (evaluation, planning and submission); the rest is GPU execution.

**Limitations.**
- 2.5D depth sorting applies to consecutive `threeD` siblings and does not cross group boundaries.

## Media and delivery

`sr-media`, `sr-audio` and `sr-deliver` turn a document into delivered files: video and image sequences decode into the compositor, the scene's audio mixes to a loudness target, and each `<output>` renders, encodes and uploads. `scene-render encode` drives the whole path.

**FFmpeg runs as a subprocess.** Probing, decoding and encoding call the `ffmpeg` and `ffprobe` executables (override with `SR_FFMPEG` and `SR_FFPROBE`) instead of linking libav. Any FFmpeg 5.1 or newer works, including builds with hardware encoders, a crashing codec cannot take the renderer down, and building needs no libav headers. There is no zero-copy import: decoded frames cross a pipe and upload to the GPU, and converted frames read back and cross a pipe to the encoder. At 1080p that is about 3 MB per frame each way, which the pipeline overlaps with rendering; at 4K and above the copies become a measurable share of the frame budget.

**Decoding is frame-accurate and runs ahead.** Each video layer gets its own decoder process that seeks with `-ss`, resamples to the asset frame rate at constant frame rate and fills a four-frame look-ahead on its own thread; a seek backwards or far ahead restarts it, and past the last frame the last frame holds. The GPU converts the raw planes (8- or 16-bit YUV at any chroma subsampling, or RGBA) to premultiplied working-space RGBA16F: YUV matrix and range from the stream, bilinear chroma, quarter-turn rotation from the display matrix, the input transfer and primaries, and straight, premultiplied or absent alpha. The transfer comes from the asset's `transfer`, else the stream's colour tags, else the colour space default; all 16 transfers decode, including PQ and HLG (with reference white at 203 cd/m² and 75 % HLG, per BT.2408) and the camera logs S-Log3, LogC3, LogC4, V-Log, C-Log3, REDLog3G10, F-Log2 and N-Log, each checked against its published 18 % grey code value. Representations (`--representation proxy`, or the output's own) swap in lighter files. Image sequences apply `missingFrame`: black, transparent, hold the previous frame, or error.

**Time controls map composition time to source frames.** `clipIn`/`clipOut`, loops, reverse, speed, `timeStretch`, `freezeAt` and time remapping resolve in the evaluator to a source time; `frameBlend` decides what happens between source frames. `none` takes the nearest frame, `frame-mix` cross-fades the two neighbours, and `optical-flow` warps both towards the in-between time along a dense motion field computed on the GPU with DIS: a luma pyramid, inverse-compositional search over 8×8 patches at stride 4, densification and a forward-backward warp. A test moves a textured image by a known offset and requires the median flow within ¼ px and the warped midpoint to beat a plain mix by five times.

**Outputs can play segments of the composition (SREP 13).** An `<output>` with `<segment>` children plays each segment's span (`from`..`to`, or between markers) at its `speed`, or through its `timeRemap`, one after another. Frame k is at output time k/fps, and there are ⌈T·fps⌉ frames for an output of duration T; a frame at a join belongs to the incoming segment, with durations compared to within a nanosecond so that spans such as 17.0–17.1 s join exactly. Each frame renders the composition at its mapped time, and a motion-blur sample dt seconds from a frame is taken dt output seconds away and mapped, so the blur covers the composition time the shutter spans at that speed. A segment's `focusX`/`focusY` (fixed, or animated in segment time) move the layout's reframing focus. Posters and thumbnails at a `time` take it as output time. A segment's `transition` child joins it to the next over a window of min(`duration`, both segments' durations) placed by its `alignment`: both sides render through their own maps, extended linearly past their spans and clamped to the project, are placed with their own focus, and combine as the transition type does (every type but `morph`; a `matte` names a node, which a join has none of). The output's `overlay` symbol renders in output time at its own size (the output's frame by default) and is composited over the placed picture. The audio is built in output time: the selected sources (by id in `audioTracks`, `role` in `audioRoles` with layer audio as `other`, or bus in `audioBuses`; all of them when none is given) are mixed in composition time with their own gain, fades, effects and ducking, and each stem is mapped through the segments. `stretch` keeps pitch (WSOLA), `resample` changes pitch with the rate, `mute` is silence, a freeze is silence and a reversal plays backwards; a remap under `stretch` runs at each key interval's mean rate. Segment i takes samples round(Tᵢ·r) to round(Tᵢ₊₁·r), and segments meet in an equal-power crossfade over `joinFade` (or the transition's window). The output's own `audioTrack` children play in output time, may duck under composition tracks' mapped stems or buses, and the composition's buses and master (normalisation measured on this programme, and the limiter) run once on the result. The output's track volume, gain and pan automation is evaluated in output time. Ducking and effect sidechains retain a bus's full input signal even when source selection excludes some of its tracks from playback. Captions follow the same map: each composition cue appears in every output interval that shows its span, including repeated visits through reversing remaps. Word timings are mapped and clipped to each visible interval; jumps omit skipped cues, and a cue left without words is dropped, and a track transcribing an audio track contributes only while that track is selected and the segment is not muted. A freeze holds the cue and word active at its composition time for the whole segment. The output's own `captionTrack` children are in output time; `resolve` transcribes one naming an output's own audio track from that track alone, in output time. With segments, captions burn over the output's frame (after the overlay) and caption files are written from the output-time cues. A poster's or thumbnail's `marker`, and each `kind="chapter"` marker, stand for the first output time that shows them (a still's marker in no segment fails; such chapters are dropped), and chapters are embedded in containers that hold them (FFmpeg's MP4 muxer starts the first chapter at 0; Matroska keeps the times). Delivery warns about a segment that starts or ends where nothing is drawn above the background, and a mapped cue shown for less than 0.7 s. An output's own audio tracks and caption tracks also play without segments, in output time from the output's `start`; the selection attributes act only with segments. CLI `--start` and `--end` override this range, including the origin and duration of an output without segments. A marker inside a remap segment stands for the first output time the curve reaches it. Rule C59 also excludes `luma` joins (a join has no node for a matte), R39 checks `audioBuses`, and C54 accepts the default `start="0"`. Segments, `output@overlay`, the output's audio selection, tracks and caption tracks, and rules C54–C59 and R38–R41 are proposed for schema 1.2 in SREP 13 (in review in sr-core), with this engine as the reference implementation; its six conformance cases in sr-core's kit pass.

**Audio is a graph mixed in 64-bit floats.** Audio tracks, the audio of video layers (`hasAudio`, following the layer's media clock sample for sample), buses and the master form a graph in dependency order; an unknown bus or a routing, ducking or sidechain cycle is an error. Tracks place their source with clip, loop, speed and reverse, keep pitch with WSOLA time-stretching when `preservePitch` is set, and with `fitToDuration` loop whole bars of the asset's `bpm` to end with the composition. Fades follow the five `fadeCurve` shapes; `volume`, `gain` and `pan` automation is sampled once per frame from the evaluator; ducking follows a peak detector with attack and release. The 16 effects are EQ bands, high-pass, low-pass, compressor, limiter, gate, de-esser, reverb (Freeverb), delay, chorus, pitch shift, noise reduction (spectral gate), stereo width, gain, distortion and telephone; dynamics effects can key from any node through `sidechain`. Layouts run from mono to 7.1.4 and first- or third-order ambisonics (SN3D/ACN), with BS.775 downmixes and constant-power panning between speaker pairs.

**Loudness follows ITU-R BS.1770-4.** Integrated loudness with absolute and relative gating, short-term loudness and 4× oversampled true peak pass the EBU Tech 3341 test signals to within 0.1 LU. `normalize="integrated"` applies one gain to reach `loudness`; `dynamic` rides a gain derived from 3-second loudness, smoothed over 3 seconds; either is followed by a look-ahead true-peak limiter at `truePeak`. WAV output is 16- or 24-bit with TPDF dither, or 32-bit float.

**Expressions read the mix.** Before the video pass, the mix produces the analysis table: per-frame envelopes of every track and audio layer in four bands (full, below 250 Hz, 250 Hz to 4 kHz, above 4 kHz, mapped from −60 dBFS to 0 dBFS onto 0 to 1) and beat times for a beat grid with a `source`, phase-fitted to spectral-flux onsets at the grid's tempo. `audioAmplitude()`, `beat()` and audio links read it, so animation driven by sound is exact rather than approximated.

**Every output codec is encoded and checked.** The 15 codecs (H.264, H.265, AV1, VP9, ProRes, DNxHR, FFV1, GIF, APNG, WebP, PNG, JPEG, OpenEXR and TIFF sequences, audio-only) and 8 containers are validated before rendering: a codec the container cannot hold, alpha in a codec without it, a sequence path without a `%d` pattern, or DNxHR below 256×120 is an error with the reason. The GPU writes exactly the bytes the encoder reads: NV12 or P010 in the output matrix and range with TPDF dither at 8 bits, 8- or 16-bit RGBA with straight alpha, or scene-linear float planes for EXR. It converts to the output colour space and transfer, and letterboxes when the output size differs. Outputs default to `colorSpace="srgb"`, which encodes with the sRGB curve; a BT.709 master needs `colorSpace="rec709"`, and PQ or HLG outputs carry `maxCll`, `maxFall` and `masteringDisplay` into the bitstream as HDR10 static metadata. Tests encode every codec, read the files back and check codes, alpha, HDR side data and audio streams.

**Hardware encoders are used when they work.** `--hw auto` (the default) tries NVENC, VideoToolbox, Quick Sync, AMF and VA-API for H.264, H.265 and AV1, keeping the first that encodes a probe frame, and falls back to libx264, libx265 or SVT-AV1; naming one family makes its absence an error; `--hw software` always uses the software encoders. SVT-AV1 needs frames at least 64 pixels high, so smaller outputs use libaom.

**Two-pass and size targets replay a lossless intermediate.** With `twoPass` or `maxFileSize`, the frames render once into FFV1 and each pass reads that file, so rendering is never repeated. `maxFileSize` derives a bitrate from the duration and audio bitrate and, if the file still exceeds the limit, lowers it in proportion and encodes again, up to four times.

**Posters and thumbnails** render at their `time` or `marker` through the output's crop/fit placement, overlay and output-owned captions, then write JPEG, PNG, WebP or AVIF, scaled to `width`. Without segments, the still's time is composition time and its overlay uses time relative to the effective output start; with segments it is output time. The output's preferred asset representation (including a CLI override) applies to the composition and overlay in serial and parallel delivery.

**Captions burn in or write sidecars** (see [typography and data graphics](#typography-and-data-graphics)); `sphericalMetadata` is written into 360 outputs (see [3D rendering and 360 video](#3d-rendering-and-360-video)).

**Destinations run after the files exist.** `file` copies; `http-put`, `s3`, `gcs`, `azure-blob` and `sftp` upload through `curl` (override with `SR_CURL`), which brings TLS, HTTP/2 and SFTP without a compiled-in HTTP stack. S3 requests are signed with AWS Signature Version 4 in the code (the HMAC matches RFC 4231 and the signing key the AWS example), path-style when an endpoint is set. Webhooks run last and post JSON listing every file with its size, SHA-256 and uploaded location, signed with HMAC-SHA256 in `X-Scene-Render-Signature`. Credentials and signed URLs are passed to curl through standard input, excluded from process arguments and failure messages. File digests are streamed with a fixed-size buffer. Upload responses are discarded without buffering. Each transfer, including retries and request writing, has a 30-minute wall-clock deadline (`SR_UPLOAD_TIMEOUT`, positive seconds); connection attempts are limited to 30 seconds or the remaining transfer budget. Credentials never appear in the document: `credentials="prod"` reads environment variables `SR_CREDENTIALS_PROD_<NAME>`.

| `s3` | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION` (default us-east-1), `AWS_SESSION_TOKEN`, `S3_ENDPOINT` |
| `gcs` | `GCS_TOKEN` (OAuth 2 access token), `GCS_ENDPOINT` |

**The stages overlap.** Audio mixes first, because normalisation needs the whole programme and the evaluator needs the analysis table. Then, per frame, the evaluator produces the FrameGraph, the renderer composites it, the output pass converts it and its readback maps while the next frame renders, and an encoder thread writes the previous frame into FFmpeg; decoders run ahead in their own processes. The report splits wall time into evaluation, rendering (with decode wait inside it), GPU/readback blocking time, and time blocked on the encoder, so the limiting stage is visible.

**Performance scenario.** `tools/perf_video.py DIR [--duration S]` writes four 1920×1080 60 fps H.264 sources with audio, a music track and the scene: four decoded video layers in quadrants, one rotating, one under a feathered ellipse mask, one screen-blended, with the music ducking under the first layer's audio and the master normalised to −14 LUFS. `scene-render encode DIR/perf_video.scene.xml` renders it to 1080p60 H.264 with AAC. The encode report shows frames per second, the stage split above (rendering, decoder wait, readback wait, encoder blocking) and the measured loudness of the mix.

**Limitations.**
- Audio effect parameters take their static values (track, bus and master `volume`, `gain` and `pan` do animate).
- An output's conversion to its colour space and transfer does not tone-map; HDR outputs convert primaries and transfer, and tone mapping comes from `colorManagement` (see [effects, transitions and colour finishing](#effects-transitions-and-colour-finishing)).
- Remote media is not fetched while rendering.
- Video layers sample without mipmaps, so strong minification aliases.
- One output renders on one GPU at a time.

## Vector graphics, deformation and rigging

Shapes, SVG, Lottie, path masks and deformers share one geometry kernel, `sr-vector`: everything becomes paths, flattens to polylines in f64 within 0.05 px on screen, and reaches the GPU through one tile encoder. Rigging, puppet solving and tracking data live in the same crate because they are geometry evaluated on the CPU; the evaluator (`sr-eval`) applies them to the FrameGraph and the compositor (`sr-gpu`) draws the result.

**The rasteriser is a tile-based design after Vello, implemented in-tree** so it draws directly into the compositor's wgpu textures. A CPU coarse stage cuts every edge at the 16-pixel tile rows and gives each tile the pieces that overlap it plus a backdrop: for each of its 16 pixel rows, the signed height of the pieces entirely to its left. A GPU fine stage (`raster.wgsl`, one 16×16 workgroup per tile) computes exact area coverage per pixel as that backdrop plus, per piece, its height within the pixel row times the fraction of the pixel to its right. No edge is clipped horizontally, so tiles never show seams, and nonzero and even-odd fills come from the same area sum. Each tile walks an ordered command list with an eight-deep layer stack for group opacity, masks in six combine modes (add, subtract, intersect, difference, lighten, darken) and alpha or luma mattes, inverted or not. Paints reuse the compositor's WGSL: solid colours and every document gradient evaluate per pixel through the shared `common.wgsl`, with the paint's transform composed onto the target's pixel grid. A CPU copy of the fine stage backs the tests: a circle's coverage sums to πr², half-pixel rectangle edges cover exactly half a pixel, and layer, mask and matte composition match their definitions. Coverage is exact for the flattened polygon, which lies inside the curve by at most the tolerance, so a 10 px circle loses under 2.2 px² of 314.

**Simple shapes rasterise together at screen resolution.** Consecutive shape and vector nodes with the normal blend mode and no mask, matte, clip or 3D placement collect into one scene in the target's pixel space and rasterise as one job, drawn with one quad; the job is cached by the hash of its nodes, so still vector art costs nothing after the first frame. Other vector nodes rasterise in their local space at their on-screen scale (limited by the texture size) and then composite exactly like image layers, so blend modes, masks, mattes, 2.5D and isolation apply unchanged.

**Shapes follow the schema's geometry.** Primitives sit in their `width`×`height` box: rectangles with `radius` or per-corner `cornerRadii` (TL TR BR BL, scaled down together when they do not fit, as in CSS), ellipses, polygons and stars with Lottie's polystar geometry (first tip straight up, roundness as tangent length) on the ellipse inscribed in the box, or on a circle of `outerRadius` units, a star's inner vertices on a circle of `innerRadius` units or the outer figure scaled by 0.5, paths from SVG path data, and `line`, which runs across the middle of its box. Strokes build closed outlines that fill with the nonzero rule, with butt, round and square caps, miter (with `miterLimit`), round and bevel joins, and inner joins through the vertex so sharp turns keep a solid winding. `strokePosition="inside"` or `"outside"` strokes twice the width and keeps the part inside or outside the fill, `paintOrder` chooses fill or stroke first, and `dash` repeats odd-length patterns twice as SVG does. Closed outlines start where SVG 2 starts them: an ellipse at 3 o'clock, a rectangle at its top-left corner (x + radius, y), both clockwise on screen; this is where trims and dash patterns begin. Trim paths cut the outline before stroking: `trimStart` and `trimEnd` are fractions of its length, `trimOffset` is in degrees (360 is one full length), and `trimMode="sequential"` treats every subpath as one outline. Pattern paints fill and stroke shapes, drawn through the coverage of the parts that use them.

**The nine shape modifiers apply in document order.**
- **repeater:** copies with a cumulative translation, rotation and scale about the box centre, fading from `startOpacity` to `endOpacity`.
- **offset-path:** moves each closed outline outwards by `amount` with the join in `mode`.
- **pucker-bloat:** moves vertices towards the centroid by `amount` percent and tangents the other way (negative puckers).
- **zig-zag:** `ridges` per segment of height `size`, corner or smooth.
- **twist:** rotates by up to `amount` degrees, growing with distance from the centre.
- **round-corners:** rounds sharp corners to the radius in `amount`.
- **wiggle-path:** displaces `detail` points per 100 px by up to `size`, moving at `frequency` per second from `seed`.
- **merge:** combines the fills of the paths before it by coverage (`add`, `subtract`, `intersect`, `exclude`); strokes of merged shapes follow each operand's outline.
- **trim:** removes `amount` percent from the end of the combined outline, shifted by `offset` degrees, `sequential` unless `mode="simultaneous"`.

**SVG imports through usvg.** `<vector shape="svg">` reads the file once per tolerance step and draws paths with their fills, strokes (dashes included), linear and radial gradients (interpolated in sRGB, as SVG does), paint order and group opacity. Clip paths become masks in the referencing element's space, and `<mask>` becomes a luminance or alpha matte. Colours convert from sRGB to the working space. Text, filters, embedded images, pattern paints and `mix-blend-mode` are reported per node and skipped.

**Lottie plays on its own evaluator.** `sr-vector` parses Bodymovin JSON (or a dotLottie archive, choosing `animation` by id) into a layer tree and evaluates it per frame instead of converting it into native nodes, because Lottie's shape model (styles applying to the shapes above them, operators such as trim and repeater acting across a group, precomp time stretch and remap) does not map one-to-one onto schema nodes. It covers:
- keyframes with Bézier easing, hold keys and spatial tangents;
- transforms with parenting, skew and split position;
- precomps, clipped to their size, with stretch and time remap;
- solids and shape layers with groups, rectangles, ellipses, polystars and paths;
- fills, strokes with dashes, and linear and radial gradients with opacity stops;
- every operator of the shape modifiers above;
- masks in all modes, track mattes, and markers or `"start,end"` frame segments.

`<slot id value>` overrides a property that names the slot through `sid`: numbers, comma lists, `#RRGGBB[AA]` colours or a JSON property. The layer's source time drives the frame, which holds at the segment's end. Expressions, images, text and effects are reported.

**The 14 deform modifiers map points of a node's local box.** Vector content deforms its flattened outline point by point after subdividing long edges; image and video layers draw as a deformed 32×32 grid mesh straight into their target, keeping rest coordinates so masks stay in layer space. Deformers do not combine with `threeD`: a deformed node placed in 2.5D is not deformed (validate and --strict do not say so). A skeleton solves its IK in its own space, so a figure may sit under a rotated, mirrored, skewed or unevenly scaled group; a mask uses its node's own coordinates, and one that lies entirely outside the node's box is reported (E20). Soft bodies deform their node through the same mesh warp (see [simulation and accessibility](#simulation-and-accessibility)).
- **bend:** turns the centre line through `amount` degrees along an arc.
- **twist:** rotates by up to `amount` degrees, fading out at `radius`.
- **wave:** a sine of `amount` px, `frequency` cycles across the box, `phase` degrees, across `axis`.
- **squash** and **stretch:** area-preserving scale along `axis` by 1 − `amount` or 1 + `amount`.
- **mesh-warp:** a `rows`×`cols` grid of control-point offsets interpolated bicubically (Catmull-Rom).
- **puppet:** as-rigid-as-possible over a 16-cell grid (Sorkine and Alexa, twelve fixed local and global iterations from the rest pose, so the result depends only on the pins). Position pins are weighted soft constraints; bend pins also fix the rotation of their cell; starch pins stiffen the cells within `amount` cell widths.
- **skin:** linear blend skinning against a skeleton's rest and current poses.
- **bulge** and **pinch:** magnify or shrink inside `radius`.
- **spherize:** maps the disc onto a hemisphere, blended by `amount`.
- **ripple:** circular waves of `frequency` per 100 px.
- **turbulence:** smooth noise of `amount` px at `frequency` per 100 px, scrolled by `phase`.
- **corner-pin:** a homography to the eight `corners` numbers.

Centres default to the box centre and radii to half the smaller side.

**Skeletons are nodes whose bones pose every frame.** Bones take `x`, `y`, `rotation`, `length` and scales relative to their parent bone, may be listed in any order, and animate like any element. A `transformConstraint` inside a skeleton applies to the bone before it. `ik` solves the chain from that bone up to the root: one bone aims, two bones use the analytic solution with `bendPositive` choosing the side, longer chains use FABRIK, and zero-length bones at the base are skipped. Skin weights come from `@weights`, a JSON file of `{"points": [[x, y], …], "weights": [{"boneId": w, …}, …]}` in skeleton space where each vertex takes the nearest sample. Without it, weights are automatic: inverse fourth power of the distance to each rest-pose bone segment, keeping the four strongest.

**Transform constraints run after animation and layout.** They are a post-pass over the frame in paint order: a constrained node's new world transform replaces the old one and carries to its descendants, and a target earlier in paint order is read already constrained. `influence` blends translation, rotation (the short way) and scale.
- **parent:** the target's world transform times the node's local one.
- **look-at:** rotates about the node's anchor.
- **follow-path:** places the node at `progress` along `path` in its parent's space, turning to the tangent with `autoOrient`.
- **copy-position**, **copy-rotation**, **copy-scale** and **copy-transform:** copy world components, or local ones with `space="local"`.
- **distance:** clamps to `minDistance`–`maxDistance`.
- **ik:** on nodes, rotates the parent about its anchor and then the node, so that the node's anchor plus `offsetX`, `offsetY` reaches the target.
- **track:** follows point `point` of tracking data `target` (the first track by default), in the footage layer's frame space when the data names `footage`; planar tracks also carry rotation and scale.

Targets may be nodes, bones or tracking data. Tracking files are read once when the program is built; a missing or malformed file is error E17. Lights follow `look-at`, `parent`, `copy-position`, `copy-transform`, `distance` and `follow-path` constraints as nodes do.

**Tracking data reads six formats.**
- JSON: `{"fps", "points", "planes", "cameras"}` with rows of frame and values.
- CSV: a header with `frame`, `track` and `x,y`, or `x0,y0…x3,y3` for planar tracks.
- Nuke: animated `name {{curve …} {curve …}}` knobs, `to1`–`to4` corner pins and `.chan` cameras.
- After Effects keyframe data, which Mocha also exports: feature centres, positions and corner pins with their `Units Per Second`.
- ASCII FBX: `Lcl Translation` and `Lcl Rotation` curves per model; binary FBX is rejected with a message.

Frame numbers without a rate are 24 fps. `stabilize` corrects a layer whose asset is some tracking data's `footage` by the difference between the tracked motion and a smoothed version: a Gaussian of σ = 2 × `stabilizeSmoothness` seconds, with 1 locking to the first sample. The correction is a translation for point tracks and a similarity for planar tracks.

**Performance scenario.** `tools/perf_vector.py DIR [--duration S]` writes 2,000 stroked shapes of four kinds at 1080p60, each with an animated trim end and rotation, plus a 30-bone skeleton whose chain follows an animated IK target and skins an image layer. `scene-render encode DIR/perf_vector.scene.xml` encodes it; the report gives geometry time (building shape geometry and tile encoding) separately from evaluation with constraints and IK and from GPU execution. Path tiling spreads across cores; building shape geometry is single-threaded.

**Limitations.**
- The rasteriser composites normal blending inside a vector scene; a non-normal `blend` applies to the whole node.
- An image or video layer with both a deformer and 2.5D placement draws undeformed.
- `<mask>` elements of shapes use the compositor's analytic masks, while path masks inside SVG and Lottie use the rasteriser.
- Text inside SVG and Lottie is not drawn; SVG filters and Lottie effects are reported and skipped.
- Camera tracks in tracking data are parsed but not applied.
- Pattern-filled parts of a shape draw above its other paints and ignore the shape's own matte.

## Typography and data graphics

Text, captions, charts, audiograms, machine-readable codes and formulas all become vector scenes in `sr-text` and render through the vector rasteriser, so a title stays sharp under any transform, takes masks, mattes and blend modes like any layer, and batches with shapes. The renderer glue (`sr-gpu/src/text.rs`) resolves the document's styles and animated values into `sr-text` inputs, caches layouts, and draws the few bitmap glyphs as textured quads.

**Paragraph layout follows the Unicode algorithms.** Text is itemised by style, font face and bidirectional level, shaped with rustybuzz (kerning, ligatures, the style's OpenType features and variation axes), broken at UAX #14 opportunities from `unicode-linebreak`, and reordered per line with `unicode-bidi`. A word wider than the line is hyphenated when `hyphenate` is set (Knuth–Liang patterns, English only), otherwise broken between characters. `wrap="balance"` searches for the narrowest width that keeps the greedy line count, `autoFit` searches the size scale within `minSize`–`maxSize`, `maxLines` and box overflow drop lines and end the last with an ellipsis or clip to the box, and `align="justify"` stretches spaces on every line except those ending a paragraph. Vertical writing stacks upright glyphs down columns from the right (`vertical-rl`) or left (`vertical-lr`), advancing by the font's vertical metrics or, when the font has none, its ascender minus descender. Spans inherit the text asset's style and apply their own `style` (a `textStyle` with its `basedOn` chain) and attributes; colour tokens resolve through the brand kit. Strokes sit inside, centred on or outside the outline, shadows blur by averaging nine offset copies, and decorations use the font's underline and strikeout metrics.

**Fonts come from the document first, then the system.** `fontFile` and `fontAsset` load files into the font database; `font` and `fallback` name families, with CSS weight, style and stretch matching through fontdb; characters a face lacks fall back to the style's other families and then to any installed face that has them, preferring colour faces for emoji. Generic families map to the first installed of DejaVu, Liberation and Noto. Output therefore depends on the installed fonts: documents that must render identically everywhere should ship their fonts as assets.

**Colour glyphs keep their format.** COLR v0 and v1 glyphs paint as vectors: layers, clips, transforms and linear, radial and sweep gradients map onto the rasteriser's layer stack and paints (conic gradients serve sweeps). CBDT and sbix glyphs, such as Noto Color Emoji, are PNG bitmaps; the renderer decodes each once and draws it as a textured quad with the glyph's transform.

**Text animators select units and offset properties.** A `textAnimator` selects characters, characters without spaces, words, lines or spans (optionally only the span with a given `role`) with a range selector (start, end and offset in percent or index; square, ramp, triangle, round or smooth falloff; smoothness; ease; forward, reverse, centre-out, edges-in or random order), a wiggly selector, or an expression selector whose `amount` expression runs once per unit with `textIndex` and `textTotal`. Each selected unit moves, scales, rotates, skews, fades, blurs, recolours its fill and stroke, tracks, shifts its baseline or offsets its characters in proportion to its selection; `scale`, `scaleX` and `scaleY` are factors (1 = unchanged) and `tracking` is in thousandths of an em, as in text styles. Animators combine as follows: offsets add, factors multiply by 1 + (v − 1)·s, `multiply` multiplies offsets too, and `replace` moves the accumulated value towards the animator's by its selection. Blurred glyphs are drawn apart in radius buckets a half-octave wide and blurred with the effects blur kernel; animated `variation` moves variable-font axes from the style's value (or the font's default) toward the target by the selector's share, with advances kept from layout (the outlines change and the line's spacing, wrapping and alignment do not, so animating a wide axis towards a narrow one leaves gaps). The 24 presets each fix a unit, timing mode, offsets in em, ease and overlap (`presetEase` names another curve: linear, quad-in, quad-out, cubic-out, expo-out, back-out or bounce-out; most presets use cubic-out, which is front-loaded, so at 40 % of the duration it is 78 % done): with M unit slots, duration D and overlap o a unit lasts D / (1 + (M − 1)(1 − o)) and starts (1 − o) of that after the previous one (`stagger` sets the step), in `order`; "in" presets rest in the offset state until their window, typewriter and word-by-word step without a fade, wave runs a sine over the duration, karaoke fills words and highlight wipes a box in behind them, scramble shows seeded letters until each character resolves, `counter` counts every number up (cubic-out, keeping decimals and thousands commas) before layout, and `mask-reveal` clips each line to its box. Units rotate and scale about the centre of their box on the line; tracking keeps each line's alignment. `textPath` places glyph centres along a path by arc length, rotated to the tangent when `perpendicular`, spread over the path with `forceAlignment`.

**Captions read six formats and write two.** Tracks come from inline cues, SRT, WebVTT (voice tags and inline timestamps become speakers and word timing), ASS (`\k` karaoke timings become word timing), TTML and ITT (clock, offset, frame and tick times), SCC (CEA-608 pop-on, roll-up and paint-on with the special-character set), or a transcription cache verified by `cacheSha256` (Whisper-style segments or a word list). Cues split into pages by `maxWordsPerLine`, `maxCharsPerLine` and `maxLines`. The default `lineBreaks="greedy"` treats source newlines as spaces, keeping existing pages and pixels unchanged. Opt in with `lineBreaks="source"` to end a line at a cue newline (`&#10;` in an inline XML attribute); the limits still wrap long source lines and page them. Blank source lines do not add empty rows, and `one-word` still pages each word. Source mode divides multiword timing spans by word length, keeping single-word times and emphasis; words without timing share the cue by length; `profanityFilter` masks common profanity. Tracks with `mode` burn or both, or the one an output names in `burnCaptions`, draw over every layer with `x` the centre and `y` the top of the caption block and `width` its box (lines break only where the pagination puts them), in the track's `style` over a default of 4.4 % of the frame height, white DejaVu Sans, line height 1.2. Pages start with their first word and last until the next page; the active word is the last one that has started. The 13 presets: classic adds a soft shadow to a style with neither shadow nor stroke, boxed-line puts a #000000B3 box behind each line, boxed-word an activeColor box behind the active word, one-word shows one word per page, karaoke lights whole words (each cross-fades to activeColor over its duration), and highlight, pop, enlarge, bounce, typewriter, fade and slide animate words or pages. Tracks an output lists in `captions`, and tracks with `mode` sidecar or both, are written next to the output as `<stem>.<track>.<language>.vtt`, or `.srt` when the source is SRT, with times relative to the rendered range.

**Data assets draw from their attributes.** Charts (bar, column, line, area, pie, donut, scatter, counter, progress) read `series` children or a CSV or JSON `src`, draw axes, value labels and number formats (`0.0`, `#,##0`, `0%`, `$#,##0.00`, `%.2f`), and draw on with the animatable `progress`. Audiograms draw the source's analysis envelopes as bars, a line, a mirrored wave, a radial circle, or a three-band spectrum. Codes (QR with its error-correction level, Data Matrix, PDF417, EAN-13, UPC-A, Code 128) encode through rxing and draw as merged module rectangles inside the quiet zone. Formulas typeset a TeX subset with the installed OpenType MATH font: math italic letters, Greek, operators and relations with TeX spacing, fractions, roots with an index, sub- and superscripts, big operators with limits in display style, `\left`/`\right` delimiters stretched to their content, text and function names, matrix environments, accents and infix `\over` fractions; the formula is centred in its box and scaled down to fit.

**Performance scenario.** `tools/perf_text.py DIR [--duration S]` writes 50 text layers at 1080p60, each with a per-character preset animator (cycling through 14 presets) and every third with a wiggly selector as well, under a burned-in karaoke caption track with word timing. `scene-render encode DIR/perf_text.scene.xml` encodes it; the report separates evaluation from text layout, animators, glyph geometry and tile encoding (layouts are cached after the first frame) and from GPU execution.

**Limitations.**
- Line breaking uses `unicode-linebreak` (UAX #14) and hyphenation embeds only the English dictionary; languages that need dictionary-based word breaking (Thai, Khmer) break between characters.
- Formulas use the built-in TeX subset; unknown commands and malformed environments report errors.
- Source-code syntax highlighting is not supported (`<code>` means machine-readable codes).
- `zDepth`, `rotationX` and `rotationY` on text animators approximate 2.5D by scaling each glyph.
- Audiograms need the delivery pipeline's audio analysis; `render` without audio draws them flat and reports it.
- Emoji inside burned-in captions use their text presentation; UPC and EAN codes carry no human-readable digits.

## Effects, transitions and colour finishing

Effects, transitions, adjustment layers, motion blur and the look pipeline all run as fragment passes over offscreen textures in the compositor's own command buffer. One WGSL module (`sr-gpu/src/effects.wgsl`) holds every built-in pass, `sr-gpu/src/fx.rs` turns effect elements into passes, and `sr-gpu/src/render_fx.rs` decides what each pass reads and where its result composites.

**A node with effects renders once without its own compositing, then composites the result.** The node draws "bare" (without its opacity, blend mode, masks and matte) into an offscreen covering its on-screen box plus the reach of its effects, clamped to the frame, except that warps (turbulent-displace, displacement-map, wave-warp, heat-haze, ripple) also cover the node's overscan past the frame as far as they reach, at most 256 px, so a plane that overscans the frame keeps its picture at the edge; groups and unsized nodes use the whole frame. The chain runs in document order, and the result composites with the node's opacity, blend, masks and matte, so masks and mattes cut the effected image, including strokes and drop shadows that reach outside the node; to run an effect after the mask, wrap the masked node in a group and put the effect on the group. The final image is cached under the subtree's content hash, the effects' animated values and, for effects that change on their own (grain, noise, light leaks, warps driven by time, custom shaders, time effects), the frame time; an unchanged node with static effects costs one draw. `enabled="false"` skips an effect and `mix` blends its result with its input. A leaf layer or shape placed in 2.5D (`threeD`) runs its chain flat on its own box, not clamped to the frame, and the result is placed through the camera about the node's pivot, as the node itself is: a blur grows, turns and foreshortens with the projection, and a camera move re-places the cached result.

**The 80 effect types share eight kernels.** A Dual-Kawase pyramid serves blur, glow, bloom, halation, drop and inner shadows, inner glow and unsharp mask; its σ is 1.45 · offset · 2^levels, measured on an impulse, so any σ costs the same per pixel. A per-pixel kernel runs 25 colour operations on straight values: most in linear light, but CDL, lift/gamma/gain, levels, color-grade (contrast, brightness), hue/saturation, selective colour, sepia, invert, posterize and threshold work on the sRGB-encoded values, where their controls (a contrast pivot at 0.5, a threshold of 0.5, 1 − x) have their conventional meaning (CDL, lift/gamma/gain, curves, levels, white balance, exposure, hue/saturation (an HSV operator: `hue` rotates, `saturation` scales the HSV saturation and `brightness` adds to V, so saturation 0 gives the grey of the maximum channel, not of the luma that color-grade's saturation 0 gives), six tone mappers, tint, tritone, gradient map and overlay, grayscale, sepia, invert, posterize, threshold, colour overlay and fill, selective colour, grain, noise, spill suppression, 3D LUTs) plus the generators and keyers (vignette, letterbox, scanlines, light leak and sweep, lens flare, fractal noise, chroma, luma and difference keys, halftone). One warp kernel serves the 18 distortions and channel offsets, a line-sampling kernel serves directional, radial and zoom blur, god rays and long shadows, a gather bokeh kernel with polygonal blades serves lens blur and tilt-shift, 3×3 kernels serve sharpen, emboss, bevel and lighting (up to four point lights from `lights`), and an alpha-morphology kernel serves stroke, outline and matte choke. LUTs load from `.cube` (1D and 3D with `DOMAIN_MIN`/`DOMAIN_MAX`), `.3dl` and CLF (LUT1D, LUT3D, Matrix, Range and ASC_CDL nodes); a single 3D table uploads as is and anything else bakes to 33³, applied in `space` through the working-to-LUT matrix and that space's transfer.

**Effect attributes are in the node's local units.** `radius`, `offsetX`/`offsetY` and pixel-valued `size` and `amount` scale with the node's transform, as layer-space parameters do in compositing applications. Where one schema attribute serves many effect types, each type reads it as follows: blur, glow, bloom, halation, inner shadow, inner glow and unsharp mask `radius` (the Gaussian σ, CSS `blur()`); glow and bloom `threshold` (on working-space luminance), `intensity`, `color` (tint), the bloom added over the content; drop and inner shadow `color` (opaque black when absent), `offsetX`/`offsetY`, `radius` (2σ for the drop shadow, CSS `drop-shadow()`), `intensity`, and for the drop shadow `compositeOriginal` (`behind`, the default, puts the shadow beneath the content, `on-top` above it, `none` shows it alone; inner shadows and glows are drawn over the content); directional blur `radius` (half length), `angle`, `samples`; radial blur `angle` (spin, else `amount` × 10°); zoom blur `amount` × 10 % zoom; lens blur `radius`, `levels` (blades, fewer than 3 = round), `angle` (blade rotation), `samples` (rings), `threshold` and `amount` (highlight boost); tilt-shift `centerY` and `size` (focus band); vignette `amount`, `radius`, `softness`, `color`, centre (darkening 1 − `amount` · smoothstep(r₀, r₀ + `softness`, r), r the distance from the centre over the half diagonal and r₀ = `radius` over it, with the schema's defaults when absent); letterbox `size` (aspect ratio, default 2.39); scanlines `size` × 4 px period; selective-color `hue` (window centre, degrees) or `color` (the window centres on its hue), `tolerance`, `saturation`, `brightness` and `amount` (the mix with the original; `channel` is not read and validate warns, E19); halftone `size` (cell, default 8), `angle` (the screen's angle, default 0, so a classic 45° screen is `angle="45"`), `color` (the ink, default black) and `paint` (the ground between the dots, default opaque white; a transparent colour leaves the picture behind showing); pixelate and mosaic `size` (cell, default 16); tile `amount` (repeats), mirrored when `size` > 1; kaleidoscope `levels` (segments); twirl, spherize and bulge `radius` (default half the frame) and `amount` or `angle`; wave warp, ripple and heat haze `amount` (amplitude), `size` (wavelength), `speed` and `frequency`; lens distortion `amount` × 0.2 (k1); chromatic aberration `amount` (pixels of shift at the input's farthest corner from its centre, red shrunk and blue magnified about it, transparent beyond the input; the input is the node's content box, the union of its and its sized descendants' boxes grown by 2 px, or the frame for adjustment layers); stroke and outline `size` (width), `color`, `position` (stroke draws the ring and keeps the content; outline draws the ring alone, with the content left out, so it can be composited separately); matte choke `amount` (positive erodes, negative dilates) and `softness`; long shadow `size` (length, default 60), `angle`, `color`; echo `samples` (copies, at most 16), `amount` (frames between copies), `intensity` (decay); posterize-time `frequency` (frames per second); pixel motion blur `amount` (shutter fraction of a frame, halved) and `samples`; film grain `amount`, `size`, `seed` and noise `amount`, `seed` (both reseeded per frame; noise draws one independent value per pixel, so it has no `size`); `source` names the node used as a displacement map or a difference-key plate.

**Seeded effects draw from the counter-based hash** described under [evaluation](#evaluation). Each effect's seed is the CRC-32 of the project seed, its id and `@seed`, and temporal effects use the frame as the channel: film grain takes normal draws per sample ((y · width + x) · 3 + channel) blurred by σ = (size − 1)/2 and weighted by (4v(1 − v))^response in linear light, noise adds uniform draws in [−1, 1) times `amount` in display values, glitch shifts rows and copies up to 256 blocks at seeded draws before its channel delay and quantisation, and VHS, fractal noise, turbulent displace, heat haze, light leak and the glitch and light-leak transitions sample seeded value-noise and fractal lattices.

**Adjustment layers act on what is already drawn.** At an adjustment layer's place in paint order the target is copied into a snapshot, the adjustment's effects run on the snapshot, and the result replaces the target within the adjustment's coverage (backdrop + (effect − backdrop) · coverage; opacity, masks and matte make the coverage) or composites with its blend mode, so layers above it are unaffected. Effects read transparency outside their input, never the clamped edge; the blur effect is a separable Gaussian with σ = `radius` (the sampled kernel over ±3σ, three box passes above σ = 4).

**Transitions draw both sides and combine them in one pass.** Within a transition window both nodes render into full-frame offscreens at the incoming node's place (the outgoing node draws nothing on its own), and the transition kernel combines them at the eased progress; an in or out transition of a single node treats the missing side as transparent. The window is centred on, starts at or ends at the cut, which is `from`'s end (`to`'s start without a `from`). Geometry is in frame pixels: `direction` is the travel (left 180°, right 0°, up 270°, down 90°, or `angle` degrees clockwise from +x); every masked type shows b where its coordinate s < e − w, a beyond e, and a smoothstep between, with e = p·(1 + w) and w = `softness` — wipe along the travel from its starting side, barn-door the distance from the centre line over half the span, circle-open and its alias iris the distance from the centre over half the diagonal, circle-close its reverse on a, clock-wipe the angle clockwise from 12 o'clock, radial-wipe from `angle`, luma the working-space Rec. 709 luminance of the `matte` sibling (which is not drawn itself); push, cover (alias slide) and reveal move pictures across the frame's span along the travel; additive-dissolve clamps at 1. The other types take `<param>` children: zoom-in/out (`amount`, `cx`, `cy`), spin, whip-pan, squash and shuffle warp the pictures in frame pixels (shrinking axes pre-filtered), blinds (`count`) and stripe (`count`, `stagger`) are masked wipes, blur and pixelize (`amount`) blur or block-average both sides around the cut, glitch and light-leak draw their slices, blocks and blobs from the seeded hash, flip, cube and carousel (`panels`) project the pictures as planes through a pinhole camera at twice the frame width, page-curl (`radius`) rolls the outgoing page on a cylinder, and film-roll (`gap`, `border`, `curvature`, `holes`) runs both frames along a curved strip; circle, clock and radial wipes take `cx`/`cy` and luma `invert`. `motionBlur` (default true) streaks push, cover, slide, reveal, whip-pan and film-roll with a 180° shutter over the eased speed. Sequence junctions use the sequence's `transition` type.

**Custom shaders are GLSL translated by naga.** `type="shader"` effects define `vec4 effect(vec2 uv)` reading `getColor(uv)`; `type="shader"` transitions use the gl-transitions convention (`vec4 transition(vec2 uv)` with `getFromColor`, `getToColor`, `progress` and `ratio`), so shaders from that collection run unchanged. Loose `uniform` declarations move into the pass's parameter block with defaults from their `// = value` comments, overridden by `<param>` children (up to 24 floats); user code sees straight, display-encoded sRGB with a bottom-left origin. naga validates the translated shader at load time and reports its errors with the file name.

**Distortion edges can be extended explicitly.** Add `<param name="edgeMode" value="1"/>` inside an effect to clamp samples to its input edge, or `value="2"` to mirror them. The default (`0`) preserves transparent sampling outside the input. This applies to chromatic aberration, RGB split, displacement map, turbulent displace, wave warp, ripple, twirl, spherize, bulge, lens distortion, heat haze, mirror, kaleidoscope, tile, pixelate and VHS. For a full-frame chromatic aberration adjustment, clamping prevents cyan bands where the red channel samples beyond the frame. Modes extend the effect input's boundary; they do not add offscreen scene content or fill transparent regions already inside it.

```xml
<effect id="aberration" type="chromatic-aberration" amount="24">
  <param name="edgeMode" value="1"/>
</effect>
```

**Motion blur and time effects evaluate the scene at other times.** `Renderer::render_with` takes a sub-frame provider (the delivery pipeline and the CLI pass the evaluator); sub-frames are evaluated once per frame and shared. A node blurs when its own `motionBlur`, else its nearest ancestor's, else the project's, is on; it samples `motionBlurSamples` times across `shutterAngle` starting at `shutterPhase`, and with `adaptiveMotionBlur` only nodes whose box moves at least half a pixel across the shutter are sampled, so still layers and groups whose children move on their own cost nothing extra. Each sample is bounded to the box its layer sweeps across the shutter plus its effects' reach. The samples accumulate additively with equal weights. Echo accumulates earlier frames with decaying weights, posterize-time draws the node as it was at the start of its posterized frame, and pixel motion blur computes the optical flow (see [media and delivery](#media-and-delivery)) between the node's previous and current frames and blurs along it.

**Effects run on targets sized to what they cover, and their results are reused while nothing they depend on changes.** A leaf layer or shape (without shape modifiers, deforms or soft bodies) runs its effect chain on a target covering its box, its stroke (half the width centred, the whole width outside, lengthened at corners by √2 for rectangles and up to the miter limit for paths, polygons and stars) and the effects' reach, at every time the chain shows: the start of the step for `posterize-time`, the trail of frames for `echo`. Other nodes, and effects without a finite reach, use the whole target. A chain's result is cached under the node as the chain shows it (its own state and transform into the target, and its subtree), its effects' parameters, the animated paints, generators and lights the subtree names (fills, strokes and other paint attributes, generator assets, effect `lights`, `paint` and `source`) and the camera; `posterize-time` counts by its step, so every frame of a step after the first reuses the first. `--stats` reports the pixels of the effect targets whose chains ran as `effect_pixels`. Stroke, outline and matte-choke sample rings around each pixel up to a radius of 4 px; wider radii gather the alpha values across the disc, preserving partially transparent and antialiased inputs without gaps. Wide gathers stop at saturated extrema, but cost grows with the radius on translucent inputs. Under motion blur a node that looks the same at every sample time apart from where it is (its own animated values other than its transform, its children relative to it, its effects' parameters and the elements it uses are equal) and has no matte and no 3D content is drawn once, at the middle of the shutter, into a target covering all it draws (not clipped to the frame, so parts entering the frame are kept), and each sample accumulates that drawing moved to the sample's transform; anything else is drawn at every sample.

**A frame spends as few passes, copies and allocations as its content allows.** Consecutive pointwise colour operations in a chain (grading, exposure, hue and saturation, tint, tritone, grayscale, sepia, invert, posterize, threshold, colour overlay, selective colour, grain and noise drawn in place, spill suppression, vignette; not curves, gradient maps or LUTs, which read tables) run as one pass of up to four operations, the pixel kept in registers between them, when each reads only the previous one's output. Effect targets that follow moving content round their size up to a multiple of 32 px so the texture sizes they need repeat; the pool keeps a size's free textures for 8 frames after it was last requested, and cache entries survive 4 frames unused (a posterized group leaves its children's entries unused between steps), their textures returning to the pool when evicted instead of being destroyed while the GPU may still read them. Add and linear-dodge are drawn by the fixed-function blender (colour dst + src, normal alpha), so they need no copy of the backdrop; the other modes copy the backdrop under the draw's bounds. Cache keys hash animated values field by field, without formatting them as text. `--stats` reports `textures_created`, `textures_released` and `subframe_seconds` (CPU time evaluating sub-frames) per frame.

**Colour finishing grades the finished frame.** `colorManagement` looks apply in order (a LUT file in the look's `space`, or ASC CDL slope, offset, power and saturation, each blended by `mix`), then `exposure` in stops, then `toneMapping` (ACES, AgX, filmic, Reinhard), before the output conversion encodes each output's colour space and transfer. With an `ocioConfig`, the OpenColorIO view replaces `toneMapping` (see [asset interop and colour](#asset-interop-and-colour)).

**Diagnosing slow renders.** Encode reports include the rendering adapter's name, backend and device type, separately from the encoder. A successful NVENC encode does not prove that scene rendering used the NVIDIA adapter. `stage_seconds[2]` (printed as `GPU/readback blocked`) measures how long delivery waits for already submitted frames after overlapping work; it is not total GPU execution time. The render stage includes planning, submission and any synchronization inside those operations. Aggregate process CPU time can exceed wall time because worker and driver threads run concurrently.

Record the scene, revision, build profile, adapter and command with any benchmark. Start with a release build and `scene-render render SCENE --bench --pipelined --stats --frames 0..120`; the JSON statistics expose cache hits, effect passes and subframes. On Linux, a CPU sampling profile can locate expensive render-stage work:

```sh
CARGO_PROFILE_RELEASE_DEBUG=line-tables-only cargo build --release -p scene-render
perf record -g --call-graph dwarf -- target/release/scene-render render SCENE --bench --pipelined --frames 0..120
perf report
```

**Quality tiers trade fidelity for speed while iterating.** `project@quality`, or `--quality draft|preview|final` on `render`, `encode` and `watch` (which overrides it), picks a tier. `final` renders as authored. `preview` keeps the resolution and uses at most 4 motion-blur samples. `draft` renders internal targets at half the document's size in its own coordinates (effects, strokes, masks and text keep their document-unit sizes, so a draft frame is the final frame at half size), with at most 2 motion-blur samples, 4 echo copies and 8 samples along a line for directional, radial and zoom blur, god rays and lens blur, and without film grain or noise. `render` writes draft frames at half size; `encode` scales them to the output's size, and its report names the tier. Proxy representations (`encode --representation proxy`) and rendering selected frames or time ranges also shorten iteration; still images, vector tiles, effect results and stable composition prefixes are cached.

**Only the frames an edit changed are rendered again.** `render --changed-only` fingerprints each frame (its time, evaluated nodes, the source text of every element it draws, the document outside the composition, the input files it names (including sequence frames and transition shaders) and the render settings) and renders only frames whose file is missing or whose fingerprint differs from the one recorded in `.scene-render-frames.json` beside the output. A scene with motion blur, time effects or included documents shows other times or files in a frame, so there any edit to the composition renders every frame (and says so). `scene-render watch FILE [--frames A..B] -o PATH [--quality Q] [--interval MS]` renders that way, then again whenever the document or a file it names changes, keeping its renderer (and its compiled pipelines) while the project, colour management, styles and input files stay the same.

Dependency scans check both authored and bound input paths. Sequence expansion has a budget of one million entries across the scan; `render` and `watch` report an error before exceeding it. Narrow `first`/`last` or increase `step` for oversized sequences.

**Performance scenarios.** `tools/perf_effects.py DIR [--duration S]` writes a 1080p60 frame with 8 effects (blur and colour grade on the backgrounds, drop shadow, glow, chromatic aberration and directional blur on two moving cards, vignette and film grain on an adjustment layer), a crossfade active over the whole timeline, and 16-sample motion blur on both cards; render it with `scene-render render DIR/perf_effects.scene.xml --bench --frames 0..120`. `tools/perf_effects.py DIR --measure BIN` benches every effect type at its default settings on a full-frame moving 1080p layer against the same scene without effects, with `SR_FX_NO_CACHE=1` so each frame recomputes the chain instead of reusing it, and prints each effect's cost over the baseline. A median effect costs about 2.5 full-frame passes (the bare render, the effect and the composite); the most expensive are long shadow (one sample per pixel of shadow length), lens blur (37 taps), echo (16 re-rendered copies), pixel motion blur (a second render plus optical flow) and tilt-shift.

**Limitations.**
- `ocioConfig` is evaluated by OpenColorIO's `ociobakelut`; without the tool it is reported and the built-in looks and tone mappers apply. `aces2` uses the ACES fit.
- Cube, flip, page curl, film roll and carousel use plane projections; `morph` displaces by luminance difference while crossfading (no dense block-matching flow).
- An effect `source` and a transition `matte` must name a node; an image asset can be placed on a hidden layer.
- Masks and mattes apply after a node's effects; blend modes inside motion-blur samples composite against transparency, and adjustment layers cannot use the time effects.

## 3D rendering and 360 video

The 3D renderer draws `object3D` nodes with physically based materials, eight light types, shadows, image-based lighting, transmission, Gaussian splats and a physical camera, and its output enters the compositor as a layer. `sr-3d` holds everything computed on the CPU (importers, primitives, animation, lights, environments, cameras, MaterialX), `sr-gpu/src/three.rs` with `three*.wgsl` renders, and `sr-gpu/src/render_three.rs` turns the document into 3D scenes and 360 frames.

**Scene space is the composition's pixel space extended into depth.** x points right, y down and z away from the default camera, and 100 scene units are one metre, which sets light falloff, IES distances, thickness and the camera's depth of field. The default camera is the 2.5D camera: it sits on the frame's centre axis at (w/2)/tan(fov/2) with a horizontal field of view (60° without a `<camera>`, the camera's `fov`, or `focalLength` over `sensorWidth`), so the z = 0 plane maps onto the frame pixel for pixel. A camera's `x`, `y` and `z` are absolute scene positions (default 0, 0, 0: the frame's top-left corner on z = 0), `yaw` turns it towards +x, positive `pitch` looks up and `roll` turns it about its axis; `target` aims it at a node. A camera or light with a `transformConstraint type="parent"` has its `x`, `y`, `z`, `yaw`, `pitch` and `roll` in the parent's frame, and an object whose `parent` is a camera or light takes that camera's or light's full 3D pose. 2.5D layers project through the same camera, including its position and rotation, so they stay registered with 3D objects when the camera moves.

**All 3D objects under one parent render as one layer.** They share one depth buffer, one set of lights and one set of shadow maps, and the layer composites at the paint position of the first of them with normal blending; group blend modes, masks, mattes and effects apply through the enclosing group, since `object3D` has none of its own; an object's `opacity` applies to that object, and `parent` links carry the transform only: opacity, visibility and timing follow the XML containment, so fading a parent object does not fade the objects parented to it. The layer renders when the compositor reaches that position, so transmissive surfaces refract the 2D layers already drawn behind them. `object3D` keeps document order among its siblings (see paint order under [evaluation](#evaluation)), so an object placed in front of the 2D plane (z < 0) paints over the layers listed before it. An object's transform is T(x, y, z) · Rz(rotation) · Ry(rotationY) · Rx(rotationX) · S, after its `parent` (a 3D object, camera or light gives its 3D world transform, a 2D node its 2D one) or else the enclosing 2D transform. `instances="N"` makes N copies, `id`, `id[1]` … `id[N−1]`, each evaluated with `index` = 0 … N − 1 and `count` = N, so any property may differ per copy; there is no implicit layout, and copies with equal transforms coincide. An object with motion blur on renders as its own 3D pass through the sub-frame sampling described under [effects](#effects-transitions-and-colour-finishing).

**Primitives are generated in scene units with outward winding.** Spheres, cylinders, cones and capsules use `radius`, `height` and `segments` with their axis along y; a box uses `width`, `height` and `depth`; a plane faces the camera and is a grid of `segments` × `segments` quads (a displacement map moves the grid's vertices); a torus lies in the xz plane with a tube radius of half its `height`, else 0.35 `radius`. `extrude` extrudes `path` (SVG path data, nonzero fill, holes allowed) and `text` extrudes the glyph outlines of `text` set in `font` at `height` pixels (default 100), centred; both run from −depth/2 to +depth/2 with a chamfered `bevel`. Tessellation uses lyon. `primitive="clay"` builds blobby surfaces (see [2D simulations, clay, lighting and path tracing](#2d-simulations-clay-lighting-and-path-tracing)).

**Models import from glTF, OBJ, PLY, FBX and USD.** glTF 2.0 and GLB bring nodes, meshes, skins, morph targets, animations, textures, the KHR material extensions (clearcoat, sheen, transmission, volume, IOR, specular, iridescence, anisotropy, dispersion, emissive strength, unlit) and `KHR_materials_variants`. `KHR_texture_transform` applies scale, rotation, offset and UV-set selection independently to each material map, including material variants and deformed meshes. glTF and PLY vertex colours multiply the material colour; OBJ brings its MTL materials; PLY brings triangle meshes; FBX goes through ufbx, converted to Y-up metres; USD reads USDA text, binary USDC and USDZ archives holding either (see [asset interop and colour](#asset-interop-and-colour)): Mesh prims with face-varying normals and UVs, transform operations, `upAxis`, `metersPerUnit` and UsdPreviewSurface materials. Y-up metre sources map into scene space with a 180° turn about x and 100 units per metre. `animationClip` names (or indexes) a clip that plays at `animationSpeed` from `animationOffset`, looping; without it a model shows its rest pose. `morphWeights` overrides the morph weights, `materialVariant` selects a variant, and a `material` attribute replaces every imported material. Skinning and morphs deform on the CPU each frame. Skinned normals use the inverse transpose of the blended joint transform, with a finite result for collapsed scales. glTF draws its default scene, or the first scene when no default is given; assets without scenes retain all nodes. Node morph weights override mesh defaults, including an explicit zero weight.

**Gaussian splats load from `.splat` files and 3D Gaussian Splatting PLY files.** Each frame a GPU radix sort (four 8-bit passes of histogram, scan and stable scatter over view depth) orders the splats back to front, and each draws as a quad sized to three standard deviations of its projected covariance, blended over the opaque scene with depth testing. Splat files use COLMAP's y-down, z-forward axes, which match scene space, scaled 100 per unit. `.splat` files carry base colour only; PLY captures also carry spherical harmonics (see [Gaussian splats](#photographic-objects-with-gaussian-splats)).

**Materials follow glTF metallic-roughness with the ratified extensions.** The shading model is GGX with correlated Smith visibility, anisotropic GGX, a clearcoat lobe, Charlie sheen, thin-film iridescence at three wavelengths, KHR_materials_specular, emissive strength and unlit surfaces; `opaque`, `mask` and `blend` alpha modes, double-sided surfaces, the five texture maps plus displacement along the normal, and UV scaling. Transmissive surfaces draw after the opaque pass and refract a mip-mapped copy of the opaque 3D result composited over the backdrop, through the material's thickness, with Beer–Lambert attenuation and per-channel indices for `dispersion`. Colours are literal colours converted into the working space; imported and MaterialX colours are linear sRGB converted into it.

**Lights use glTF's physical units.** Point, spot and area lights give `intensity` in candela and directional lights in lux, with distances in metres, `falloff` as the distance exponent and `range` as a smooth cut-off; `colorTemperature` multiplies the colour by the Planckian locus, and `exposure` scales by powers of two. Lights are binned into 16-pixel screen tiles on the CPU (forward+), 63 per tile. Rect and disk lights are one-sided and, like sphere lights, shade through a representative point on an equivalent sphere with roughness widened by its size. IES profiles (LM-63, TILT=NONE) bake into 128 × 32 tables sampled by angle from the light's axis. A dome light's `environment` (Radiance `.hdr` or OpenEXR, which are linear, or an 8- or 16-bit image, which is sRGB-decoded) is prefiltered on the CPU into 512-wide GGX-convolved mips and SH9 irradiance for diffuse, with a split-sum BRDF table; `environmentVisible` draws it behind the scene at the source's resolution (up to the device's texture limit). The image's centre column is the dome's +z, and the dome's `yaw`, `pitch` and `roll` turn the environment as they turn a camera. Directional shadows fit an orthographic box to the casters (four cascades under a perspective camera, see [lighting](#2d-simulations-clay-lighting-and-path-tracing)), spot lights use a perspective map and point and area lights six cube faces, all in one depth-array texture sampled with 3 × 3 PCF widened by `shadowSoftness`. An ambient light is a uniform environment of its colour, reflected by the diffuse and the specular lobe alike, so metals reflect it. A document without lights gets a neutral rig: ambient 0.35 and a directional key from the upper left front whose irradiance π · 0.65 brings a white Lambertian surface facing it to 1.

**The physical camera sets exposure, depth of field, distortion and shake.** `exposure` is in stops, `lensDistortion` is a radial k1, and `shake` children add fractal-noise offsets, roll and zoom within their time range: the camera moves `amplitude` · N₀ right and `amplitude` · N₁ down, rolls `rotation` · N₂ degrees and zooms by 1 + `zoom` · N₃, with N₀ to N₃ the four fractal noise channels. With `depthOfField`, the circle of confusion is f²/N · |1/focus − 1/depth| scaled to pixels through `sensorWidth`, focusing at `focusDistance` or on `focusTarget`, gathered with `apertureBlades` polygonal blades. A tile pass finds each 16-pixel tile's largest circle of confusion and dilates it by the blur's reach, so sharp regions skip the gather and blurred ones sample only as far as the local blur. Depth of field applies to 3D objects; 2.5D layers stay sharp. The main pass is 4× multisampled. The 3D pass keeps its render targets between calls, keyed by size, format, mip count, samples, layers and role, and frees those unused for 64 calls; every pass clears or fully overwrites its targets, and a test checks that a frame rendered after others matches a cold render.

**MaterialX documents supply constants and texture graphs.** The first `standard_surface`, `open_pbr_surface` or `gltf_pbr` node supplies the material. Named graph outputs resolve within their scopes; arithmetic, mixing, clamping, remapping, vector and channel operations evaluate constants or bake image graphs into linear texture maps. Base colour, normal, roughness, emission, occlusion and displacement graph outputs use the corresponding renderer slots. Cycles, missing connections and unknown operators return errors. Direct image references remain file-backed; baked colour maps preserve HDR factors separately from their normalized pixels. Graph evaluation honors image address modes (periodic, clamp, mirror and constant), closest/linear/cubic filtering, and tiled-image UV and real-world sizing controls. Direct image graphs retain closest/linear/cubic filtering and periodic/clamp/mirror/constant addressing through raster, path-traced, and CPU displacement sampling. Composed graphs bake the unit UV tile; compatible image samplers propagate through pointwise operations, while transformed or mixed-sampler graphs use the baked tile. Graphs are limited to 1024 connected nodes and a 512 MiB aggregate image/bake budget. Individual images use a 256 MiB decode budget and a 32,768-pixel dimension limit, and resize to at most 4096×4096 before float conversion. Baking uses two passes to avoid retaining a float copy of the output.

**360 video renders six cube faces per eye and reprojects them.** With `<scene360>`, every frame renders six 90° faces from the viewport camera's eye (`viewportCamera`, else the active camera), turned relative to that camera, and a reprojection pass writes `equirectangular`, `cubemap` (3 × 2: right, left, up / down, front, back), `eac` (YouTube's 3 × 2 equi-angular layout: left, front, right / down, back, up, the second row turned 90°) or `fisheye-180` (equidistant). `width` and `height` size the whole output frame; `top-bottom` and `left-right` stereo split it between eyes offset by ±`interpupillary`/2 (in metres). Plain 2D layers outside isolated groups are placed in space as 2.5D layers at their depth, so a title card floats in front of the viewer. Delivery renders at the `scene360` size unless the output sets its own. With `sphericalMetadata`, MP4 and MOV files receive Google Spherical Video V1 (XMP) and V2 (`st3d`, `sv3d` with `equi` or `cbmp`) metadata, written into the finished file with chunk offsets adjusted.

**Performance scenario.** `tools/perf_3d.py DIR [--duration S]` writes a 1080p60 scene with 207,936 sphere triangles (a 114-segment sphere drawn as 16 instances placed on a 4×4 grid by `index`) over a floor, a glass slab with dispersion, four spot lights casting 2048² shadows, and a camera focusing on the spheres; the spheres turn and the lights orbit, so every frame is new work. Render it with `scene-render render DIR/perf_3d.scene.xml --bench --frames 0..120`. `tools/perf_3d.py DIR --measure BIN` benches the scene and variants without shadows, transmission and depth of field, and prints each feature's cost next to geometry and lighting; `--bench` also reports mesh draws, triangles and splats.

**Limitations.**
- MaterialX is translated by parameter mapping; the MaterialX shader generator is not linked.
- USD time-sampled attributes take their first sample (USD animation is not imported). FBX imports its hierarchy, skins, blend shapes and animation stacks.
- Light lists are binned on the CPU and splats are drawn as sorted quads rather than by a tile rasteriser.
- Area lights use the representative-point approximation. Shadow maps share one resolution, capped so that all shadow views fit in 512 MB.
- Spherical metadata is written for equirectangular and cubemap video in MP4 and MOV; EAC and fisheye-180 need V2 mesh projections, which are reported.

## Simulation and accessibility

Physics and particles accumulate state over time, which conflicts with rendering any frame on its own. Both therefore run in `sr-sim` as fixed-step simulations from their start time, keeping a copy of their complete state at every simulated second; a frame reached by seeking reuses the nearest available copy, and the result is bit-identical to a straight run whatever order frames are requested in. `sr-eval` builds the simulation from the document and applies it to every evaluated frame, so every renderer, the CLI and delivery see simulated frames without further wiring.

**Rigid bodies run on Rapier 2D in double precision with enhanced determinism.** The world is metres with y up; `physics@pixelsPerMeter` (default 100) maps it to document pixels with y down, and gravity defaults to −9.80665 m/s². A `rigidBody` on a layer or shape takes the node's box (`box`), its inscribed or `radius` circle (`circle`), a capsule along its longer side (`capsule`), the convex hull of `path` (`polygon`), a convex decomposition of `path` (`path`) or the convex hull of the layer image's alpha (`convex-hull`), at the node's pose when physics starts; the simulated pose then replaces the node's world transform and its children follow, including explicit `parent` links and their descendants. A child with its own rigid body keeps its own simulated pose regardless of paint order. Cycles combining containment and explicit transform parents are rejected as E11 before evaluation. Kinematic bodies, and dynamic bodies before `activateAt`, follow their animation; `collisionGroup` and `collidesWith` filter contacts, `sensor` bodies detect without colliding, `bullet` enables continuous collision detection, and `velocityX`/`velocityY` are pixels per second. `bounds="floor"` and `"frame"` add walls around the frame, which take each body's own friction and restitution (in 3D too). The eight constraint types map to Rapier joints: `hinge` and `motor` are revolute joints (with angle limits and a motor of `motorSpeed` degrees per second), `slider` is prismatic along `axisAngle`, `weld` is fixed, `rope` limits distance, `spring` is a spring of `stiffness` and `damping`, `distance` is a stiff spring, and `pin` holds a body at a world point (rigid, or springy when `stiffness` is given); a joint whose impulse exceeds `breakForce` is removed.

**Rigid bodies in 3D run on Rapier 3D, in the same way.** A `rigidBody` inside an `object3D` makes the object a body of a second world stepped beside the 2D one, with the same step, checkpoints, gravity (plus `physics@gravityZ`, toward the camera) and bounds (`floor` is a ground plane at the frame's bottom edge, `frame` a box around the frame as deep as it is wide). The body starts at the object's 3D pose when physics starts, in its 3D parent's frame (`@parent` or a parent constraint) or its 2D container's, and the simulated pose then replaces the object's transform: objects parented to it follow, and cameras and lights can target it. `shape="auto"` (the default) uses the primitive's own form: a box for `box` and `plane`, a sphere, cylinder, cone or capsule where the object's scale keeps it round, and the convex hull of any other mesh (a torus, an extrusion, a mesh asset). `box`, `sphere`, `capsule`, `cylinder` and `cone` force an analytic shape; `convex-hull`, `trimesh` (the exact triangles, for static and kinematic scenery, rule C48) and `decomposition` (convex parts of a closed mesh by V-HACD) use the object's triangles, from a mesh asset in its rest pose. `velocityX`/`Y`/`Z` are pixels per second and `angularVelocityX`/`Y`/`Z` degrees per second, in scene axes (y down, z away from the camera). Constraints between two 3D bodies take a 3D anchor (`x`, `y`, `z`) and an axis (`axisX`, `axisY`, `axisZ`; z by default for `hinge` and `motor`, x for `slider`), and add `ball`, a ball-and-socket joint; a constraint cannot join a 2D body to a 3D one. `breakForce` compares the joint's linear force in newtons. Force fields act in 3D too: `z` places a radial field's centre in depth and `forceZ` pushes toward the camera. The 3D `rigidBody` (which needs `version="1.2"`), the constraint attributes `z`, `axisX`, `axisY`, `axisZ` and type `ball`, `forceField` `z` and `forceZ`, `physics@gravityZ` and rule C48 are proposed for schema 1.2 in SREP 11 (in review in sr-core), with this engine as the reference implementation.

**Soft bodies are spring-mass lattices.** `jelly` and `cloth` simulate a lattice of (`rows` + 1) × (`cols` + 1) points over the node's box with structural and shear springs, and cloth adds bend springs across two cells; jelly's springs all have the body's `stiffness`, while cloth's shear springs have 0.15 of it and its bend springs 0.02, so it drapes; jelly's `pressure` restores its rest area; `rope` is a chain of `cols` points along the node's centre line. `stiffness` is in newtons per metre, `damping` a fraction of critical damping of each spring, `mass` the total mass; `pin` fixes an edge or the corners and `selfCollision` keeps points apart. Integration is symplectic Euler in substeps of about 1/ω with ω = √(8k/m) per point, and validation rejects a body needing more than 4096 substeps per `fixedStep` (code P01). Points collide one way with the rigid bodies and the bounds. The node stays at its start transform and the lattice deforms its drawing through the vector mesh warp, so layers and shapes deform alike.

**Force fields are accelerations in metres per second² with +y up,** converted to pixels by `pixelsPerMeter`, like gravity. `directional` and `wind` (gusting with noise) push along (`forceX`, `forceY`); `radial` pulls toward (`x`, `y`, composition pixels) with positive `strength` and pushes away with negative; `vortex` turns around it, clockwise on screen for positive `strength`; `turbulence` follows curl noise of feature size `scale` × 100 px; `drag` opposes velocity (`strength` per second); `attractor-path` pulls toward the nearest point of `path`. `radius` (in metres) bounds a field with a (1 − d/r)^`falloff` weight, otherwise the weight falls as (d/100 px)^−`falloff` beyond 100 px; `start`, `end` and animated values apply, and `affects` restricts a field to bodies or particles. Bodies receive mass × acceleration.

**Particles are simulated on the CPU in structure-of-arrays form and drawn as instanced quads.** Emission is deterministic: `rate` particles per second (animatable) with birth times spread within each step, plus `burst` children (at `time` on the emitter's clock, like its keys: composition time, not offset by `start`), from a point, a centred rect, ellipse or line, points along `emitterPath`, or opaque pixels of `emitterAsset`, turned by the emitter's world transform; each particle's variances come from a counter-based hash of the emitter seed and its index. Particles move under `gravityX`/`gravityY`, `drag`, curl-noise `turbulence` and the force fields named in `forceFields` (all particle fields when absent, none with `useForceFields="false"`; flocks and fluids read both the same way), bounce off the bounds and the physics bodies with `collide`, and live in frame space once born. `preroll` starts the simulation earlier so the system is full at `start`; `maxParticles` caps the live count. Group `timeOffset` and `timeScale` place and advance particles on the emitter's timeline, including nested groups, bursts and animated rates, independently of the first requested frame. Remapped, looping and held instance clocks replay source history for the branch nearest the requested frame; this can cost more than checkpoint reuse. Trimming or holding a source still simulates its earlier particle births. Emitters attached to physics bodies use the body pose at each birth time, from the live simulation or its cache. Size runs from `size` to `sizeEnd`, colour from `color` to `colorEnd` and opacity from 1 to `opacityEnd` along `sizeCurve` and `colorCurve`. Shapes are antialiased discs and squares, sprite-sheet cells of an image (`spriteCols` × `spriteRows`, advancing at `spriteFps` or chosen per particle), or streaks along the velocity; `trail` adds a fading streak behind each particle. The particles render into an offscreen that composites with the emitter's opacity, blend mode, masks, matte and effects. The ten presets fill in every attribute the document leaves at its schema default, so `preset="fire"` with an explicit `rate` keeps that rate.

**A physics cache replaces the simulation.** `scene-render simulate FILE [-o CACHE]` runs the physics to the end of the document, writes every step's body poses (3D bodies as a position and a quaternion) and soft lattices to `physics@cache` (or the named file) and prints the `cacheSha256` value; with a cache present and its digest matching, frames read from it instead of simulating. Validation rejects a mismatched digest (A02); the evaluator also checks it and simulates when it fails. Caches written before 3D bodies existed (format version 1) still read.

**Accessibility checks run on the rendered frames during delivery.** They run when the document declares `<accessibility>` in its metadata; without the element nothing is checked (the XSD defaults belong to the element's attributes), so `<accessibility/>` alone turns on the flash check at `warn`. `flashCheck` (default `warn`) follows ITU-R BT.1702 and WCAG 2.3.1: each frame reduces on the GPU to a 48 × 27 grid in display-referred linear light; a general transition is a relative-luminance change of at least 0.1 whose darker state is below 0.8, a red transition involves saturated red (R/(R+G+B) ≥ 0.8) with a change of (R−G−B) × 320 above 20; a cell flashes with eight or more opposing transitions (more than three flashes) in a second, and a frame fails when flashing cells cover more than a quarter of any window one third of the frame wide and tall, the 10° field at the reference 1024 × 768 geometry. `contrastCheck` measures burned-in text and captions: the compositor copies the target just before each text layer or caption burn-in in the frame's own target draws, and after the frame the pixels the text changed give the text's luminance from the frame and the background's from the copy, so the ratio is (L1 + 0.05)/(L2 + 0.05) against what is actually behind the glyphs; the lowest ratio per text below `minContrast` is reported. Text drawn inside an isolated group, mask, matte or effect never meets the final backdrop in its own target, so the renderer lists it instead, and after the pass delivery renders every frame at that text's maximum accumulated opacity twice, with and without that layer: the pixels that change are its glyphs as delivered (faded, blended or filtered), measured the same way. Output overlays and output-time captions are measured with and without each text layer or caption burn-in over the placed picture, including the overlay's own background and covering layers. If text changes no colours, two additional renders replace its ink with black and white while preserving alpha, masks, transforms and covering layers. Their difference establishes visible coverage: identical text and backdrop colours report 1:1, while transparent, fully covered, offscreen and empty text produce no measurement. These additional renders and readbacks run only when `contrastCheck` is enabled. `requireCaptions` accepts composition or output-owned caption tracks and checks their presence before encoding, for serial and parallel delivery alike. Rendered-frame findings go to the delivery report's `accessibility` list; a flash or contrast check set to `error` fails the delivery once encoding finishes.

**Performance scenario.** `tools/perf_physics.py DIR [--duration S]` writes 200 rigid bodies (boxes and circles) falling in a frame-bounded world under a vortex field, a jelly, a pinned cloth and three emitters (fire, sparks that collide with the bodies, and snow) with up to 12,000 live particles at 1080p60. Every frame advances the simulation, so nothing is served from caches. Render it with `scene-render render DIR/perf_physics.scene.xml --bench --frames 60..120`; evaluation includes every simulation step of the frame, and the bench reports it separately from CPU planning and submission and from GPU drawing.

**Fuzzing.** `sr-fuzz` mutates the conformance corpus and built-in seeds (byte flips, span deletion and duplication, splices, boundary attribute values, nesting bombs, truncation) through validation, loading, instantiation and evaluation, and generates and mutates expressions through parsing, compilation and execution. `cargo run --release -p sr-fuzz -- --seconds N` runs a campaign of that length and writes any crashing input to `fuzz-crashes/`.

**Limitations.**
- Particles use plain structure-of-arrays loops left to the compiler's auto-vectorisation rather than explicit SIMD.
- Soft bodies are spring-mass lattices integrated in substeps, not position-based dynamics, and couple one way: they collide with rigid bodies but do not push them.
- Particle collisions with physics bodies use the bodies' state at the frame being rendered, not at each particle step.
- A body with motion blur renders its own sub-frames from the same simulation; rigid-body descendants reached only through `@parent` links do not follow the body.
- 3D bodies meet only 3D bodies: 2D bodies, soft bodies and particles do not collide with them. Clay and map objects collide as a sphere of their `radius` unless given a shape, and text objects as their box.
- Sprites are drawn untinted (opacity only); flash analysis samples each grid cell on an 8 × 8 lattice.

## 2D simulations, clay, lighting and path tracing

**Schema.** Beyond the original scene-render 1.1 elements, the canonical schema includes, first implemented here: the composition nodes `<flock>`, `<fluid>` (with `<fluidSource>`), `<slime>` and `<erosion>`; `object3D primitive="clay"` with `<blob>` children and the attributes `resolution`, `fingerprints`, `boil` and `seed`; the camera attributes `ambientOcclusion`, `aoRadius`, `aoIntensity`, `screenSpaceReflections`, `renderer`, `pathSamples`, `maxBounces` and `denoise`; and the light attributes `contactShadows` and `contactShadowLength`. Every addition is optional, with defaults that leave documents that do not use it unchanged. Other engines may not implement them yet.

**2D simulations.** All four run on the node's own timeline in 1/60 s steps (`sr-sim/timeline.rs`) with a checkpoint every simulated second, so frames can be requested in any order and match a straight run. For states too large to copy every second (millions of slime agents), checkpoints are thinned to a 256 MB budget.
- `<flock>` is Reynolds' boids: separation, alignment and cohesion within `perception`, capped at `maxSpeed` and `maxForce`, with a cruise `speed`, kept in the box by `bounds` (steer, bounce or wrap), and pushed by the named force fields. It draws like particles: streaks oriented to the velocity, discs or sprites.
- `<fluid>` is Stam's stable fluids on a staggered grid (`resolution` cells along the longer side). Sources add dye and velocity; `buoyancy`, the force fields and `vorticity` confinement act; `viscosity` diffuses; the velocity is projected divergence-free by successive over-relaxation (`iterations`), advected semi-Lagrangianly and projected again; the premultiplied colour dye is advected, diffused and dissipated. Semi-Lagrangian advection loses dye, so closed and wrapped boxes rescale each dye channel to its total before advection.
- `<slime>` is Jones's Physarum model: three sensors, turning, deposit, then 3 × 3 diffusion and decay, drawn through a two-colour ramp.
- `<erosion>` is Beyer's droplet erosion of a fractal (or `heightmap`) terrain, hill-shaded under a sun. A droplet that stops inside the map deposits what it carries.

The unit tests check behaviour, not pixels:
- a flock's polarisation rises above 0.8 with alignment and stays disordered without it, and separation keeps pairs apart;
- projection drives divergence below 1/1000 of its start, dye is conserved in a closed box, and dissipation is exponential;
- a slime network's contrast is more than twice that of agents that do not sense;
- erosion moves material from the highest tenth of the terrain to the lowest.

GPU tests check that each simulation draws, changes over time, and gives the same frame whether a time is reached directly, by playing or by seeking back.

**Clay.** `object3D primitive="clay"` joins its `<blob>` solids (sphere, box, capsule, torus; positioned, rotated and sized, each animatable) as signed distance fields, with polynomial smooth unions of width `blend` or smooth subtraction. `fingerprints` displaces the surface with smudges and ridges, and `boil` re-seeds that displacement a number of times per second, the jitter between frames of hand-animated clay. The surface is extracted every frame by naive surface nets at `resolution` cells along the object's longest side, so blobs merge and split as they move, and the renderer re-meshes only when the blobs, the finish or the boil frame change. A sphere meshes closed, with its volume within 2 % and outward normals; blobs merge and split; subtraction carves.

**Screen-space lighting and shadows.** When a camera turns on `ambientOcclusion` or `screenSpaceReflections`, or a light turns on `contactShadows`, the 3D pass first runs a depth and normal prepass (view normal, roughness, view depth and split-sum reflectance).
- Ambient occlusion takes 16 hemisphere samples per pixel, rotated per pixel and range-checked, then a depth-aware blur, and darkens only ambient and environment light.
- Contact shadows march 16 steps toward the light against the prepass depth, catching detail the shadow map misses.
- Reflections march the reflected ray in view space with per-pixel jitter and bisection, reject hits on surfaces seen from behind, fade at the frame's edges, on rough surfaces and for rays toward the camera, and replace the environment's share of the specular reflection.

Directional lights under a perspective camera cast through four shadow cascades (the practical split scheme), each fitted to its slice of the view within the scene, and the shadow budget is 512 MB. A thin pole on a 20 000-unit floor casts a visible shadow at 512 texels, which a single map fitted to the scene does not. Tests check each effect's darkening or reflection where it belongs and no change elsewhere.

**Path tracing.** `camera renderer="pathtrace"` traces the 3D pass instead of rasterising it (`sr-gpu/pathtrace.rs`, `pathtrace.wgsl`), `pathSamples` paths per pixel of at most `maxBounces` bounces.
- The prepared scene is flattened on the CPU (instances expanded, deformed vertices, materials, lights) under a binned-SAH bounding volume hierarchy.
- A compute shader traces in dispatches of four samples: thin-lens camera rays for depth of field; next-event estimation with shadow rays to every analytic light, sampling area lights on their shape; the rasteriser's Lambert and GGX BSDF sampled by lobe; smooth dielectric transmission; Russian roulette; and the dome and ambient light for rays that leave.
- Rays leaving through glass see the 2D layers where they meet the composition plane.
- `denoise` applies five passes of an edge-aware à-trous filter guided by first-hit albedo and normals.
- The random numbers are a hash of pixel and sample, so a frame renders identically every time.
- Texture maps, displacement, vertex colours, Gaussian splats with spherical-harmonic colours, IES profiles and lens distortion are supported. The tracer shares map coordinates with the rasteriser and includes splats in its acceleration structure. Shadow rays respect texture alpha masks and blending.
- Perspective and orthographic cameras use the full projection, including resized offscreens.

Tests:
- The BVH finds the same nearest hits as brute force.
- Traced frames match the rasteriser for a white furnace (ambient light only) and for a directional light.
- A sphere shadows the floor, and glass shows the red layer behind it.
- The denoiser halves the pixel-to-pixel variation while keeping the mean.

**Limitations.** Shadow rays treat glass as opaque (no caustics), and indirect light samples are clamped against fireflies. Geometry, textures and frame buffers that exceed device limits fall back to rasterisation with a diagnostic.

## Asset interop and colour

**FBX animation stacks.** The FBX importer keeps every node with its parent and local transform. Skin clusters become joints with `geometry_to_bone` as the inverse bind; blend channels become morph targets; and every animation stack is baked by ufbx, with pivots, pre- and post-rotations and rotation orders resolved, into linear translation, rotation and scale keys, with the blend channels' `DeformPercent` keys as morph weights. Clips take their stack's name for `object3D@animationClip`. `tools/fixtures/make_fbx_rig.py` has Blender export a rig (a bar skinned to a two-bone armature that bends and moves, a spinner under a moving parent, a shape key), and the test poses the import at three times against Blender's own evaluated vertices, to 2 mm. In-between blend shapes use their full shape, and only a mesh's first skin is used; both are reported.

**Binary USD.** `sr-3d/src/usdc.rs` reads crate files (version 0.4 and later) without new dependencies: the table of contents; USD's LZ4 chunk wrapper, over a small LZ4 block decoder; the integer compression of its tables; the token, string, field, field-set, path and spec tables; and value representations, meaning inlined scalars, vectors and diagonal matrices, compressed int, int64 and float arrays (integral and lookup-table codings), strings, tokens, asset paths, token and path vectors and list ops, and time samples. The specs become the prim tree the USDA parser builds, so both share the mesh, transform and material mapping, and a USDZ may hold either kind of layer. `tools/fixtures/make_usd_stage.py` has usd-core write one stage as USDA, USDC and USDZ: all three must import alike and reproduce USD's own world-space points. `make_usdc_values.py` writes 31 attributes, one per value coding, which must decode as USD reads them. Time-sampled attributes take their first sample in both formats, and the renderer reports that USD animation is not imported.

**OpenColorIO.** OCIO is a C++ library without a C interface, so instead of linking it the renderer runs OCIO's own `ociobakelut` (in the `opencolorio` Python wheel and every OCIO build, found through `SR_OCIOBAKELUT` or `PATH`), the way it runs FFmpeg. The config's transform from the working space through its looks to `display` and `view` is baked onto a 129³ lattice indexed by the ACEScct curve of each working channel, which covers scene-linear values up to about 222 and follows the working space's own axes, where configs clamp. When the working space is ACEScg and the config's ACEScct matches the renderer's (checked with a 17³ bake), the table comes straight from it. Otherwise the bake goes through the config's log space (`compositing_log`, `color_timing` and similar) with a 65,536-entry shaper, and is resampled. A bake takes about 2 s, once per renderer. In finishing, exposure applies first; the frame is then encoded onto the lattice, looked up, and the display code values are decoded with the first output's colour space and transfer (sRGB without outputs) back to display-linear working colour, which the output stage re-encodes exactly. The OCIO view replaces `toneMapping`. `@workingSpace` must be one of the renderer's spaces, found in the config under its usual names; `ocio://` built-in configs work. `@looks` lists `<look>` elements: under `ocioConfig`, a `<look>` with neither `src` nor CDL values names a look of the config, while the others still apply as the renderer's own looks. `tools/fixtures/make_ocio_expected.py` has PyOpenColorIO compute display values for nine colours at three exposures through the built-in ACES CG config (the ACES 2.0 SDR view) and through a small config with a LUT file, a log shaper and a CDL look. The rendered frames match them to within 0.015, which is the trilinear error of the table at the gamut boundary (0.011 measured against OCIO's analytic CPU path) plus half-float storage. Without the tool, `ocioConfig` is reported and the built-in pipeline applies.

## Photographic objects with Gaussian splats

A 3D Gaussian Splatting capture (Kerbl et al. 2023) turns an object photographed from all around into splats that render photographically, including its view-dependent shine, which makes it the cheapest route to real props in stop-motion-style work.

**Capture and reconstruct.** Photograph the object in 60 to 200 overlapping pictures from every side, with exposure, white balance and focus locked, soft even light and nothing moving. The object should fill most of each frame, and a turntable with a plain backdrop works well. Reconstruct with a 3DGS trainer and export a `.ply`. Options include the reference implementation (COLMAP camera poses, then its training script, which writes `point_cloud/iteration_*/point_cloud.ply`), nerfstudio's `splatfacto` (`ns-process-data`, `ns-train splatfacto`, `ns-export gaussian-splat`), or a capture application that exports 3DGS PLY. These tools change, so check their own documentation for the exact commands. Before use, crop floaters and background in a splat editor (SuperSplat, for example) and export PLY again.

**Bring it in.** Reference the file as `<mesh src="capture.ply" format="ply"/>` and draw it with `object3D primitive="mesh"`. A PLY whose vertices carry `f_dc_*` and `scale_*` imports as splats: positions, scales (`exp`), rotations, opacities (a sigmoid) and colour, including the spherical harmonics of degree 1 to 3 (`f_rest_*`, channel-major). The renderer evaluates the harmonics per splat for the direction from the camera in the capture's own frame, as 3D Gaussian Splatting does, so highlights stay put while the object turns. One unit of the capture becomes 100 scene pixels. Captures are usually y-down or z-up and in arbitrary units, so set `rotationX` or `rotationY` and `scaleX`/`scaleY`/`scaleZ` on the `object3D` until it stands upright at the right size. Splats sort back to front on the GPU every frame, mix with meshes through the depth buffer, and take the object's `opacity`. `examples/splat/` has a turntable: `python examples/splat/make_splat.py` writes a synthetic vase in the same file format (degree-3 harmonics with a lobe toward a light), and `turntable.scene.xml` spins it.

**Limitations.** Splats are not relit by the scene's lights and cast no shadows (they carry the lighting of the capture); the harmonic coefficients cost 192 bytes a splat on the GPU; and the `.splat` format has no harmonics.

## Still images: formats, orientation and colour

Every still the renderer reads (image layers, sequences, patterns, sprites, shader and material textures, simulation seeds, environment maps) goes through `sr_media::still::open`.

**Formats.**
- In-process: PNG, JPEG, WebP, GIF, TIFF, BMP, TGA, QOI, PNM, ICO, DDS, farbfeld, Radiance HDR and OpenEXR (the `image` crate), and JPEG XL (`jxl-oxide`).
- HEIC, HEIF and AVIF prefer the `heif-convert` executable from libheif (`libheif-examples` on Ubuntu/Debian; override with `SR_HEIF_CONVERT`). This handles HEIF item layouts and identity-matrix AVIF that some FFmpeg versions decode incorrectly. If unavailable or unsuccessful, decoding falls back to FFmpeg. Install libheif for the verified HEIC/AVIF path. Formats the in-process decoders refuse (PSD, JPEG 2000, SGI, PCX and others) also use FFmpeg, reading one frame at the source bit depth.
- Animated GIF and APNG play as `<video>` sources through FFmpeg; FFmpeg does not decode animated WebP, which loads its first frame.
- The AVIF and HEIC libraries are not linked into the renderer; external decoders run as subprocesses.

**Orientation.** EXIF orientation is applied, so phone photos come out upright (JPEG XL's codestream orientation is applied by its decoder).

**Colour.** A file's own colour description takes precedence over the asset's `colorSpace` and `transfer`, which now apply only to files without one; `colorProfile="declared"` restores them for data textures and mis-tagged files.
- ICC profiles of the matrix/TRC kind (sRGB, Display P3, Adobe RGB, ProPhoto, Rec. 2020, grey; curves as gammas, tables or parametric functions) are read by `sr_media::icc`, from PNG, JPEG, WebP, TIFF and JPEG XL files and from HEIF `colr` boxes (which FFmpeg does not pass on).
- H.273 code points (HEIF `nclx`, the ICC 4.4 `cicp` tag) map onto the named spaces and transfers, PQ and HLG included.
- A profile equal to a named space (within ICC's fixed-point rounding) takes that space's exact path, so sRGB-tagged images decode exactly as before; any other profile decodes through its own curves and colorants, adapted from ICC's D50 to D65 with Bradford.
- A profile that cannot be used (CMYK, lookup-table printer profiles, damaged) is reported, and the declared colour space applies.
- OpenEXR, Radiance HDR and floating-point TIFF are linear light, so `transfer="auto"` means linear for them.

`tools/fixtures/make_still_formats.py` writes one 12 × 8 pattern in every format, ICC-tagged PNGs from profiles it builds (Display P3 with a parametric curve, a v2 gamma 2.2 Adobe RGB, a tabulated curve, grey), HEIC files tagged by ICC and by `nclx`, an EXIF-rotated JPEG and a CMYK JPEG, with LittleCMS's (Pillow's ImageCms) sRGB conversion of every tagged pixel. The tests decode every lossless format to the exact pattern, HEIC within 3 steps of libheif, and the tagged files within 1/255 of LittleCMS (4/255 for lossy HEIC), and render a P3 image both ways.

## Maps

Maps are drawn as vectors from geographic data, so they go through the same compositor, effects, masks and trim as any shape, and stay deterministic (no tiles loading in a browser). The `sr-geo` crate holds the geography: d3-geo's spherical pipeline, ported and checked against d3 itself.

**Data.** `<geo src="…">` reads GeoJSON, TopoJSON (`object` picks one object), KML (placemarks with their extended data) or GPX (waypoints, routes, tracks). Polygon edges are great-circle arcs, as in d3. Data wound the RFC 7946 way would enclose the rest of the globe, so a polygon larger than a hemisphere is turned round on reading.

**Projections.** `<map projection="…">` takes Mercator, Web Mercator, equirectangular, Equal Earth, Natural Earth, Albers, Lambert conformal conic (both with `parallels`), orthographic, stereographic, and azimuthal equal-area and equidistant.
- Geometry is rotated on the sphere and clipped there: cut along the antimeridian opposite the centre (polygons rejoined along the cut, and a polygon round a pole, like Antarctica, wrapped round it), or, for the globe and azimuthal views, clipped to the visible cap.
- Edges are then resampled adaptively, so long lines curve as they should, projected, and clipped to the frame.
- `tools/fixtures/make_geo_expected.mjs` records what d3-geo 3.1 and topojson-client make of the Natural Earth 110 m countries (world-atlas) under 13 setups: every projection, rotations that cut Russia, Fiji and Antarctica differently, rectangle clips and plane rotation. For all 177 countries the areas, bounds and ring counts must match d3's, and the full coordinates of Russia, Fiji and Antarctica must match to 10⁻⁶ pixels, as must fitted scales and van Wijk paths.

**The camera.** `zoom` counts doublings from the fitted view: zoom 0 shows `fit` (geo assets; the whole sphere by default) inside the frame less `fitPadding`, centred on `centerLon`/`centerLat` (default: the middle of the fit target). Web Mercator uses MapLibre's zoom levels instead, a 512-pixel world at zoom 0. `centerLon`, `centerLat`, `zoom` and `rotation` animate like any attribute; a globe spins by animating `centerLon`.
- `<flyTo begin lon lat zoom>` moves along van Wijk and Nuij's smooth zoom-and-pan path, as d3's `interpolateZoom` and MapLibre's `flyTo` do: it zooms out as far as the distance warrants, takes the short way round the antimeridian, eases by `easing`, and lasts `duration` (by default the path's natural length).
- The first move starts from the map's own centre and zoom and each later one from the previous target; once a move has begun, the moves decide centre and zoom.
- Tilt a map in perspective with its layer's 3D rotation.

**Content,** painted in document order over `background` (the globe or world outline filled) and under `outline`:
- `<geoLayer>` fills polygons, strokes lines (drawn on by `progress`; polygon outlines are always drawn whole) and dots points, filtered by `prop=value`/`prop!=value` conditions.
- For a choropleth, `fillBy` names a numeric property mapped through `domain` and a `linear`, `log`, `sqrt` or `quantize` scale onto `palette`, interpolated in sRGB like d3's `interpolateRgb`; features without a value take `noData`.
- `<featureStyle key="…">` restyles single features (matched on `keyBy`, the feature id by default) and animates, so a country can light up. Neighbouring features with the same paint fill as one shape, so their shared borders leave no anti-aliasing seam.
- `label` names a property drawn at each feature's centre.
- `<graticule step>` draws meridians and parallels.
- `<route points="lon,lat …">` (or the lines of a geo asset) follows great circles and is drawn on by `progress` measured along the ground, so it advances at constant ground speed in any projection; `headRadius` puts a dot at its tip.
- `<pin lon lat label>` marks a place, hidden on the far side of a globe.

**Placing any layer.** The expressions `geo('map', lon, lat)` and `geoVisible('map', lon, lat)` give where a place lands on a map now (in map pixels, following its animation and fly-to moves) and whether it is visible, so a photo or a caption can ride on a spinning globe and fade as it turns away.

**Validation.** R36, R37 and R26 require `geoLayer/@geo`, `route/@geo` and every id in `map/@fit` to name geo assets, latitudes and longitudes are bounded, `route/@points` must be `lon,lat` pairs, C53 requires a `domain` to increase, and C45 requires a route to have `points` or `geo`.

**Tests.**
- World features land where they belong on an equirectangular map, with a border pixel filled without a seam.
- Choropleth colours come out at the right values, including quantize and no-data.
- An animated feature style changes colour.
- A globe hides its far side, and a fly-to ends on target.
- A route stops at half its ground length with its head there.
- KML and GPX draw.
- Web Mercator matches tile geometry.
- `geo()` follows a spinning globe, and `geoVisible()` turns off on the far side.
- A geoLayer naming a non-geo asset fails validation (R36).

**Basemaps.** `<tiles>` names a tile archive and `<basemap tiles="…">` draws it under the map's other content.
- **Archives:** `<tiles>` carries a plain credit line (`attribution`) and a `sha256`, and no licence attributes. Tiles come from a PMTiles archive (`src`, version 3, with leaf directories and gzip; `sr-geo/pmtiles.rs`), such as a Protomaps basemap extract made with `pmtiles extract`. An online service (`url` with `{z}/{x}/{y}`) is fetched by `scene-render resolve --allow-cloud` into a PMTiles `cache` pinned by `cacheSha256`. The resolver works out the tiles from every frame's view at the zoom the renderer will draw, including the elevation tiles a 3D map's terrain samples and the whole world a globe drapes, fetches them one at a time with an identifying User-Agent, and refuses more than `SR_TILES_MAX` (2000), so a render never touches the network and no service is bulk-downloaded.
- **Tile selection:** tiles are chosen by walking the tile quadtree and keeping each tile whose outline, projected like any geometry, reaches the frame. A globe therefore gets its visible cap and a conic map what it covers. Vector tiles are drawn from the floor of the map zoom (as MapLibre does), and raster tiles at the zoom nearest their pixel size; beyond the archive's deepest zoom the parent tile's quarter is drawn. `detail` shifts the zoom.
- **Vector tiles** (MVT; `sr-geo/mvt.rs`) are drawn through a MapLibre style (`mapStyle`: a style JSON file, or the built-in `protomaps-light` and `protomaps-dark`). The style engine (`sr-geo/style.rs`) evaluates filters, legacy functions and expressions: `match`, `case`, `coalesce`, `interpolate` (linear, exponential, cubic-bezier), `step`, `format`, comparisons, arithmetic, conversions and `let`/`var`.
  - Fills of one paint are drawn as one shape, so tile and feature borders show no seam.
  - Lines get width, dashes, caps, joins and casings.
  - Circles are drawn as dots.
  - Text labels are placed without overlap, the style's upper layers and lower sort keys first: at points with variable anchors, radial offsets and wrapping, or along roads, upright, with halos.
  - Web Mercator views place tile geometry through an exact affine map; other projections go through the spherical pipeline.
- **Raster tiles** are drawn as images cut into cells whose corners are projected, so they bend into any projection and stop at a globe's edge. They are painted beneath all of the map's vector content, its `background` included, so a map with an opaque background hides them; that is reported.
- **Attribution:** the tiles' `attribution` (or the archive's) is drawn in the map's corner as a credit line (`attribution="false"` leaves it out).
- **Clipping:** a map is clipped to its frame.
- **Not supported:** style layers other than `background`, `fill`, `line`, `circle` and `symbol` (skipped and reported), icons (sprites) and fonts named by the style (labels use the renderer's fonts with the style's weight and slant); line labels follow a straight segment, not the curve.
- **Performance:** a five-second flight from the Atlantic down to Lisbon's streets renders at a median of 20 ms a frame at 720p on the RTX 6000 Ada.

**3D maps.** Two `object3D` primitives bring maps into the 3D renderer, where the 3D camera, lights and shadows act on them.
- **`primitive="map"`** lays a map asset down as ground in the object's xy plane, one map pixel per scene unit, like a layer that can be tilted with `rotationX` or orbited.
  - **Drape:** the ground wears the map exactly as the 2D renderer draws it (basemaps, layers, routes, pins, labels). It is laid out at the map's own size, so lines and labels keep their 2D size, and rasterised on the CPU at `textureSize` along its longer side (`sr-gpu/drape.rs`: raster tiles warped in first, then the vectors through the fine stage the GPU runs, in parallel bands), and cached until the map's animated state changes.
  - **Terrain:** `terrain` names tiles of elevation (Terrarium, or Mapbox Terrain-RGB with `terrainEncoding="mapbox"`), sampled at the zoom that gives about one elevation pixel per grid cell. They raise a grid of `resolution` cells toward the camera by the true height at the map's scale times `exaggeration`, relative to the height at the map's centre, with normals from the slope.
  - **Buildings:** `buildings="true"` extrudes the footprints in the `buildings` (or `building`) layer of the map's first vector basemap from `min_height` to `height` (or `render_height`; 8 m without one), standing on the terrain, in the object's `material`.
  - **Material:** the object's `material` also dresses the ground: its base colour multiplies the drape and its roughness, metallic and unlit apply (without one, white at roughness 0.9).
  - Terrain and buildings need a web-mercator map, whose screen points invert exactly to longitude and latitude; other projections are draped flat.
- **`primitive="globe"`** wraps a sphere of `radius` (poles on the y axis, 0° longitude facing the camera; `rotationY` turns it, negative angles bringing the west forward) in the map's content drawn over the whole world in equirectangular, laid out 2H × H map pixels (H the map's height) and scaled to `textureSize`.
- **Elevation data:** the AWS Terrain Tiles (Terrarium) service works through `scene-render resolve`, for example `<tiles id="dem" url="https://s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png" maxZoom="15" cache="dem.pmtiles" …>`.
- **Tests:** a globe turns the right region to the camera; a Terrarium hill seen edge-on rises above the flat ground line, and only with `terrain`; Lisbon's buildings seen edge-on stand up in their material, and only with `buildings`.

**Not yet.** Label collision for pins and geo layers (basemap labels avoid each other), simplification of detailed data, and 3D terrain on a globe. The whole file is read into memory, so 1:10 m data is slow to fit; `fit` is cached per map setup.

**Schema.** `colorProfile`, `<geo>`, `<map>` with its children, the two expression functions and the rules R26, R36, R37, C45 and C53 are part of the canonical schema, first implemented here. `<tiles>` and `<basemap>` (rules R27 and C46), and the `object3D` primitives `map` and `globe` with their attributes (rules R28, R29 and C47), are proposed for schema 1.2 in SREPs 9 and 10 (in review in sr-core), with this engine as the reference implementation. Other engines may not implement them yet.

## Generated media and transcription

A document names provider-made media as `<generated>` assets and transcribed captions as `<captionTrack transcribe="…">`. Rendering never calls a provider; it reads the cache and refuses it unless its SHA-256 equals `cacheSha256`, so a render is repeatable. `scene-render resolve` (the `sr-resolve` crate) is the step that makes those caches.

```xml
<generated id="vo" kind="speech" provider="piper" model="en_US-lessac-medium"
           prompt="Twelve months, three launches." cache="gen/vo.wav" cacheSha256="0000…"/>
<generated id="bed" kind="music" provider="audioforge" model="bed/documentary-airy"
           prompt="duration=auto bpm=96" seed="7" cache="gen/bed.wav" cacheSha256="0000…"/>
…
<captionTrack id="subs" language="en-US" transcribe="voice" model="base.en"
              cache="gen/subs.json" cacheSha256="0000…"/>
```

**What a run does.**
- Each target becomes a request whose key hashes what decides the result: provider, model, prompt, voice, language, seed, size, frame rate, duration, the audio format, the cache file extension, where the asset plays and, for a transcription, the input audio. Local Piper and Whisper model files are hashed too, including Piper's adjacent `.onnx.json` configuration: different models cannot collide just because they have the same relative filename, while identical files can share results across projects. Apart from the extension, cache paths and ids are not part of the key. Entries made before the extension was included are regenerated on the next resolve.
- A target is up to date when the sidecar `<cache>.resolve.json` records the same key and the cache's digest, and `cacheSha256` matches. If only the attribute is wrong, it is re-pinned. Otherwise the result comes from the store (`SR_RESOLVE_STORE`, default `~/.cache/scene-render/resolve`), where every result is kept by key, so the same request in another document or after a clean checkout costs nothing. Only when neither has it does the provider run. `--force` ignores both, and `--no-store` leaves the store alone.
- Generated media come first, so captions can transcribe speech made in the same run. A transcriber hears the track as it plays in the scene's mix (placement, trims, speed, loops, volume and effects), as a mono WAV from composition time 0, so the word times it returns are composition times.
- `cacheSha256` is rewritten in the document's text; comments, layout and every other attribute stay as they were. Placeholder digests (all zeros) are the usual starting point.
- `--check` makes and writes nothing and exits 1 when anything is stale, for CI.
- A `cache` path must stay inside the document's folder, including when written as an absolute path or `file:` URI. Paths that leave it through `..` or symlinks are refused before a provider runs. `SR_RESOLVE_ROOT` names a wider folder to allow, for projects that keep scenes and media in sibling folders. Cache files, sidecars and document updates use exclusively created temporary files and atomic replacement.

**Providers.**
- `whisper`, the default transcriber: whisper.cpp's `whisper-cli` (`SR_WHISPER`, else `PATH`). `model` names a ggml model (`base.en`, `small`, `large-v3`) found in `SR_WHISPER_MODELS` or the `models/` folder of the whisper.cpp tree, or is a path. Audio is resampled to 16 kHz, `language` and `prompt` pass through, and the tokens are joined into words timed by dynamic time warping (`--dtw`), which whisper.cpp offers for the standard models.
- `piper`, local speech: `model` is a voice, found as `<model>.onnx` in `SR_PIPER_VOICES` or `~/.local/share/piper`, or a path; a numeric `voice` picks a speaker. piper samples noise, so two runs differ slightly, and the pinned cache keeps the one the document uses.
- `audioforge`, music and sound effects from AudioForge's cue library (`SR_AUDIOFORGE`, else `PATH`): `model` is the cue, `prompt` its parameters, `seed` the performance seed. `duration=auto` fills the project after the track that plays it starts, and the audio format follows `audioMix`.
- `openai` (speech with `/audio/speech`, images with `/images/generations`) and `elevenlabs` (speech) send the prompt to a cloud service, so they run only with `--allow-cloud`. They need `OPENAI_API_KEY` or `ELEVENLABS_API_KEY`, and `OPENAI_BASE_URL` and `ELEVENLABS_BASE_URL` point them at compatible servers. Requests go through `curl`, with the key in curl's configuration on standard input rather than on a command line.
- Any other name runs the program in `SR_PROVIDER_<NAME>` or a `scene-render-provider-<name>` on `PATH`, which also overrides a built-in of that name. The program reads one JSON request on standard input (kind, provider, model, prompt, voice, language, seed, size, duration, the audio format, the timeline, the output path with the cache's extension, a scratch folder and, for transcription, the input WAV) and answers `{"ok": true, "version": "…"}` or `{"ok": false, "error": "…"}` as the last line of its output. A transcriber writes `{"segments": [{"start", "end", "text", "words": [{"start", "end", "text"}]}]}`. `scene-render-provider-example`, built with the crate, implements the protocol as a reference. Provider pipes are drained concurrently with bounded response buffers.
- `tiles` fetches the map tiles an online `<tiles url>` service provides for the document's views into a PMTiles cache (see [Maps](#maps)); it too needs `--allow-cloud`.
- A result whose extension differs from what the provider makes is converted by FFmpeg.

All providers share a per-target subprocess deadline, including conversion and retries: `SR_PROVIDER_TIMEOUT` sets positive seconds (default 1800). Captured stdout/stderr are limited to 1 MiB each, and cloud downloads to 256 MiB. Curl ignores user configuration; cloud diagnostics report status without echoing remote bodies or stderr that may contain credentials. Scratch directories are exclusively created and private on Unix.

**Schema.** `captionTrack` gains `provider` (default `whisper`), `model` (default `base`) and `prompt` for the transcriber; these are part of the canonical schema, first implemented here. This is the only active scene-render engine; the C and Python engines are discontinued for now (sr-core SREP 25).

**Tests.**
- With the example provider: speech and its captions are made and pinned, the captions start where the track plays, the document validates afterwards with nothing else changed, and a second run makes nothing.
- A changed prompt is stale under `--check`, which writes nothing, and resolving remakes the speech and the captions that heard it; a hand-edited digest is re-pinned.
- The store restores deleted caches without the provider, and `--force` and `--only` behave as described.
- Images, a refused cloud provider, and an unknown provider.
- OpenAI speech and images against a local HTTP server, checking the key header and the request bodies.
- When installed: piper speech captioned by whisper.cpp (the words are found, in order, after the track's start), and an AudioForge cue at the mix's sample rate.

## Reference-clip evidence

`tools/evidence.py [OUT_DIR] [--bin PATH] [--case ID]… [--bench]` checks individual rendering techniques used by reference styles. These pixel checks establish technical behavior; they do not measure composition, continuity or artistic quality. Each case in `tools/evidence/cases.json` names a reference style and one technique it depends on, and either a probe scene in `tools/evidence/scenes/` or none. The harness writes the probe (generating any asset it needs: a Gaussian-splat torus, an animated glTF, an OCIO config), renders the frames its checks name with `render --strict`, compares pixels (a colour at a point, the share of a region near or away from a colour, the change of a region between two times) and classifies the case:

- **native**: `--strict` passes and every check passes;
- **degraded**: the checks pass, but the renderer reported a fallback;
- **wrong**: a check fails, so the frame is not what the scene asks for;
- **error**: the scene did not render;
- **gap**: no probe exists because the engine has no feature for the technique.

Each case records the outcome last accepted as `expect`, and any difference fails the run (exit status 1) in either direction, so changes to accepted outcomes require review. A failed `native` expectation must be investigated before changing the manifest. `--bin` accepts an executable path or a command found on `PATH`; the resolved executable is used for both rendering and hashing. The run writes `report.json`, `report.md`, per-frame logs and `contact-sheet.png`, records the checkout commit, dirty status and renderer binary hash, with `--bench` adding frame times for cases marked `bench`. The manifest currently holds 24 cases: 22 expect native and 2 expect degraded. A clip whose technique has no probe yet enters as a `gap` with its reason. The OCIO case needs `ociobakelut` on `PATH` or in `SR_OCIOBAKELUT`.

CI runs all 24 probes in an independent job and uploads their reports and images even when another job fails. Install the Python dependencies with `python3 -m pip install -r tools/evidence/requirements.txt`; the pinned OpenColorIO package supplies `ociobakelut`.

Two complete micro-scenes add motion typography with held timing and a lit 3D product setup. Run them with:

```sh
python3 tools/evidence.py target/review --manifest tools/evidence/review.json --clips
```

Clip destinations are absolute during encoding, and a missing or empty clip fails the run instead of publishing a broken link. Each produces a 3-second, 640×360, 24 fps MP4 plus sampled frames, motion/hold checks and manual review prompts. Review the full clips for spacing, cadence, silhouettes, lighting, flicker and transitions into the final holds. Passing the automated checks is not an artistic approval. Outputs are regenerated, so choose a disposable output directory.

| Case | Outcome | Evidence |
|---|---|---|
| stop-motion replacement sequence, 12 fps on twos, missing frames held | native | exact code values per frame |

## Performance and verified platforms

**Performance scenarios.** Each subsystem ships a generator for a heavy scene, with the same command-line arguments: `tools/perf_layers.py` (compositing), `tools/perf_video.py` (decode, audio and encode), `tools/perf_vector.py` (shapes, trim paths and rigging), `tools/perf_text.py` (animated text and captions), `tools/perf_effects.py` (effects, transitions and motion blur), `tools/perf_3d.py` (meshes, shadows, transmission and depth of field), `tools/perf_physics.py` (rigid bodies, soft bodies and particles) and `tools/perf_impact.py` (an impact shot without media files: a posterize-time group with a noise backdrop, focus lines and particles, a stroked title, a blurred layer under motion blur, a warp adjustment and a finishing grade with grain). Each takes an output directory, writes a `.scene.xml`, and is measured with `scene-render render --bench` or `scene-render encode`, as described in the subsystem sections above. `perf_effects.py` and `perf_3d.py` also take `--measure BIN` to attribute cost per effect or per feature. `--bench` reports median and p95 frame time and the CPU share; `encode` reports the stage split. Absolute timings depend on the GPU and the number of CPU cores, so run the scenarios on the target machine.

**Measuring a change.** With `--stats`, where the adapter has timestamp queries, `render` measures GPU time: each frame's and every effect pass's (labelled node/effect) join the per-frame statistics as `gpu`, and `--bench` also prints `gpu: median … ms` of GPU work per frame beside the CPU's share. Timing every pass costs time itself (much of it on llvmpipe), so a plain `--bench` stays untimed. `tools/perf_gate.py BASE_BIN HEAD_BIN` benches `perf_impact` and `perf_effects` (frames 0..30) with the two binaries in alternating rounds (`--rounds`, default 3) on the same machine, compares each binary's best median and exits 1 when a fixture is more than `--threshold` (default 0.15) slower with the new one; CI runs it on every push and pull request against the base commit. `tools/perf_suite.py OUT.json` runs the fixture suite (the seven scenarios with `--bench`, `perf_video` and `perf_text` with `encode --end 5`, and with `--beta SCENE` a real programme: two frame ranges, a clip and the audio-only mix) and records every figure, the adapter and the commit; `--baseline BASE.json` prints the baseline/new ratio per fixture and their geometric mean, and exits 1 when a fixture regressed below 0.95. `tools/equivalence.py --baseline BIN --candidate BIN` renders frames of every fixture with both binaries as 16-bit PNG and compares the SHA-256 of the decoded pixels, and compares the audio-only mix of `perf_video` by the SHA-256 of its WAV data chunk: a performance change is accepted only when it passes unchanged (the golden tests tolerate small colour differences; this check does not). `--threads N` (or `SR_THREADS`) caps the CPU worker threads (the tile encoder, audio analysis), which does not change results but makes timings reproducible. `render --bench --pipelined` keeps one frame in flight, waiting for the previous frame's submission instead of draining the queue after each frame, so its figure is throughput rather than latency.

**Verified platforms.** The CI workflow (`.github/workflows/ci.yml`) uses Ubuntu 24.04 with Mesa lavapipe, the software Vulkan driver (`SR_GPU_BACKEND=vulkan`), and FFmpeg software encoders. Independent jobs run the full test suite, the evidence probes and review clips, performance smoke renders and 600-second fuzzing, and the conformance corpus plus differential oracle (`tools/oracle_diff.py 2000 1`). A golden failure does not prevent the other jobs from running. Diagnostic artifacts include GPU/driver and dependency versions; golden thresholds remain PSNR ≥ 50 dB and maximum ΔE2000 ≤ 1. `crates/sr-gpu/tests/backends.rs` renders pattern paints, a scene mixing particles, blend modes, effects, an adjustment layer and a mask, and every valid conformance-corpus document at its start and middle on OpenGL and on the native backend and requires PSNR ≥ 40 dB between them (on Mesa both are llvmpipe; CI installs Mesa's EGL and GL drivers for it). What OpenGL cannot draw it reports as not rendered, so `--strict` fails, and such frames are not compared: 3D objects are not drawn on OpenGL, whose shaders cannot read the multisampled depth the 3D pass resolves, and float targets use the widest format the device renders to (32-bit where it can, 16-bit on OpenGL). Windows and macOS jobs check compilation of all targets and run model, evaluator and provider unit tests, including executable discovery with Windows `PATHEXT`. Those checks do not establish visual equivalence on Metal, DirectX 12, discrete GPUs or hardware encoders; those still require rendering and review on the target hardware.

## CLI

`scene-render validate FILE… [--format human|json] [--no-assets] [--base-dir DIR] [--deny-warnings] [--quiet]` prints rustc-style diagnostics with source excerpts, or one JSON document for scripts. Exit status is 0 for valid, 1 for invalid (or warnings under `--deny-warnings`), 2 for usage or I/O errors. Colour follows `--color`, `NO_COLOR` and terminal detection. `inspect` summarises the typed model or dumps it with `--json`; `explain` describes any code; `completions` prints shell completion scripts.

`scene-render render FILE [--time T | --frame N | --frames A..B] -o PATH [--bit-depth 8|16] [--variant --layout --param --row --data] [--bench] [--stats] [--strict] [--quality Q] [--changed-only]` renders on the best available adapter (see *Choosing the GPU* below) and writes display-referred sRGB PNGs with straight alpha; several frames need `%04d` or `{frame}` in the path. `--bench` renders into GPU memory only and reports median and p95 frame time with the CPU share; `--stats` prints per-frame draws, targets, cache hits and backdrop copies as JSON lines; with 3D content `--bench` also reports mesh draws, triangles and splats. Motion blur and time effects evaluate sub-frames through the same evaluator. A frame whose media cannot be read is an error with exit status 1. Content the renderer cannot draw as authored — unsupported nodes, a shader effect whose GLSL fails (it passes its input through) or a shader transition that fails (it crossfades) — is listed as `note: not rendered yet: …` and the command still succeeds; `--strict` makes those notes and evaluator warnings exit with status 1 (the files are still written), so a successful exit proves every requested effect ran. `SR_FX_NO_CACHE=1` disables reuse of effect results between frames, so `--bench` measures the full cost of every effect chain.

**Choosing the GPU.** Every adapter of the enabled backends is ranked: discrete GPUs first, then integrated, unknown and virtual ones, and software rasterisers last (any adapter of type `Cpu`, or named llvmpipe, lavapipe, softpipe, SwiftShader or the Microsoft Basic Render Driver, which some drivers report as another type). Between equal devices a native backend (Vulkan, Metal, DirectX 12) beats OpenGL. `SR_GPU_BACKEND=vulkan|metal|dx12|gl` restricts the backends and `SR_GPU_ADAPTER` picks the first adapter whose name contains its value, ignoring case; a name that matches nothing is an error listing the adapters found. `scene-render gpus [--json]` lists them and marks the one renders use. `render` and `encode` warn when they render on a software adapter, and encoding on one keeps the automatic worker count at one (an explicit `--parallel N` is honoured). Parallel worker devices are opened sequentially on the caller's selected adapter and retained until all workers finish; independent devices avoid allocation contention while rendering and encoding segments concurrently. On WSL2, where the Vulkan loader finds only lavapipe, the CLI routes OpenGL through Mesa's D3D12 driver to the host GPU: when `/dev/dxg` and `d3d12_dri.so` exist and `GALLIUM_DRIVER` is unset it sets `GALLIUM_DRIVER=d3d12`, and when the NVIDIA driver is mapped into WSL and `MESA_D3D12_DEFAULT_ADAPTER_NAME` is unset it names the NVIDIA GPU; `SR_GPU_WSL=off` disables this. Library users call `sr_gpu::gpu::prepare_environment()` at program start for the same behaviour.

`scene-render simulate FILE [-o CACHE]` writes the physics cache and prints its `cacheSha256`.

`scene-render resolve FILE [--check] [--force] [--only ID…] [--allow-cloud] [--no-store] [--json]` makes the caches of generated media and transcribed captions and pins their `cacheSha256` in the document (see [Generated media and transcription](#generated-media-and-transcription)). Exit status is 1 when a target fails, or under `--check` when one is stale.

`scene-render encode FILE [--output ID…] [-o PATH [--codec CODEC]] [--out-dir DIR] [--representation NAME] [--hw auto|software|nvenc|videotoolbox|vaapi|qsv|amf] [--start T] [--end T] [--no-upload] [--parallel auto|N] [--param ID=VALUE] [--row N [--data ID]] [--json] [--strict]` renders every `<output>` of the document, or those named with `--output`, including posters, thumbnails and destinations. `-o` replaces them with one ad-hoc output whose codec follows the extension (`.mp4` H.264, `.mov` ProRes, `.mxf` DNxHR, `.mkv` FFV1, `.webm` VP9, `.gif`, `.webp`, `.png` APNG or, with `%d`, a PNG sequence, `.jpg`, `.exr` and `.tif` sequences, `.wav`, `.m4a` and `.mp3` audio-only) unless `--codec` names one. Relative paths resolve against `--out-dir`, else the document's directory. Each output reports its files, encoder, frame rate achieved, stage timings, loudness, evaluator warnings, content not rendered yet and accessibility findings, retaining findings from every parallel chunk; `--strict` exits with status 1 when any output has evaluator warnings, unsupported content or accessibility findings; `--json` prints the report as one JSON object per output. Progress goes to standard error on a terminal. `--parallel` renders a single-pass video output as time segments at once, each with its own renderer and encoder starting on a keyframe, and joins them without re-encoding, muxing the one audio mix: `auto`, the default, takes 3 segments with a hardware encoder and otherwise half the cores up to 4, at least 20 s each, and `1` renders serially. A frame renders the same whichever frame a render started from, so a lossless output decodes to the same frames either way and a lossy one differs only by the extra keyframes at the joins. Two-pass and `maxFileSize` outputs, sequences, GIF, APNG, WebP, audio-only outputs and documents with a simulation render serially. Flash and contrast checks do not: what each segment's frames show is judged in frame order over the whole output, so the findings are those of a serial render.

Encoding reports preserve template diagnostics in `evaluation_warnings`; human output includes their codes and locations. `encode --strict` fails on these evaluator warnings, including unresolved `{{placeholders}}`, as well as unsupported content and accessibility findings. Output files are still written. Asset warnings such as `A07` remain warnings; use `validate --deny-warnings` to reject them.
