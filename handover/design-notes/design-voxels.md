# Design note V.1: voxel assets, the `voxels` primitive and the schema

Facts first. sr-3d depends on sr-media and sr-vector only, sr-volume has no dependencies and sr-sim depends on sr-volume and rapier only; sr-eval depends on all of them. The collider voxelizer is `sr_sim::pyro::mesh::Mesh` (a closed, validated parry TriMesh, a point test by the nearest oriented surface) and `voxelize` samples cell centres. There is no `.vox` file on this machine (`find / -name '*.vox'` finds none), so the format below is from the MagicaVoxel description as I know it and has to be proved by fixtures and by one real file that somebody brings.

## 1. The asset: `<voxelAsset id src format sha256 license credit proxy model fromMesh cellSize maxCells maxMemoryMiB voxelGrid>`
- Source, exactly one of `src` or `fromMesh` (VOX2). `src` with `format="vox"` (MagicaVoxel) or `"srvol"` (default from the extension); `fromMesh` names a `<mesh>` asset (VOX3) and `cellSize` (scene units, positive, required with `fromMesh` and forbidden with `src`) is the edge of the cells it is cut into.
- The provenance group of the other assets (`sha256`, `license`, `credit`, `proxy`); a `sha256` that does not match is an error as for the others.
- `model` (integer, only for `vox`): absent, the whole scene of the file, models placed by its scene graph (nTRN/nGRP/nSHP, frame 0, the rotation byte and the integer translation), or the single model of a file with no scene graph; present, that model alone, unplaced.
- `maxCells` (occupied cells, default 4 194 304, at most 67 108 864) and `maxMemoryMiB` (default 128, at most 4096), both checked BEFORE allocating, by the size of the file for `vox`, by the bounding box of the mesh over `cellSize` for `fromMesh`; over the limit is an error that names the number, never a truncation.
- `voxelGrid` (the channel of an `srvol`, default `voxels`): a grid whose values are the palette indices 1 to 255 as exact floats, background 0; its transform gives the default cell size.

## 2. What the importer makes
An `sr_3d::Occupancy` (Netuno's type: sparse bricks of 8^3, palette index per cell, revision = hash of the cells) plus `Option<[ [u8;4]; 255 ]>` (the file's colours, index c is entry c-1, as the file stores them offset by one) and the MATL properties by index (`_type` diffuse/metal/glass/emit, `_rough`, `_metal`, `_trans`, `_ior`, `_emit`/`_flux`, mapped to base colour, roughness, metallic, transmission, ior, emissive; the rest are ignored and said in the SREP). Axes: MagicaVoxel is x right, y forward, z up (right-handed); the scene is x right, y down, z forward (right-handed): `scene = (x, -z, y)`, a half turn about x composed with a swap, determinant +1. A file with no RGBA chunk uses MagicaVoxel's built-in palette, which I do NOT build in (I could not check a 256-entry table from memory): the import then needs `palette` to give materials and says so otherwise. Where it lives: the parser in `sr_3d::voxel` (`vox.rs`, std only, no dependency; each chunk length checked against the bytes left, sizes against the limits before reading, every index checked), the `srvol` conversion in sr-3d too (one new edge sr-3d to sr-volume, a crate with no dependencies), `fromMesh` in sr-eval (it is the only crate that sees both the mesh asset and the sr-sim voxelizer): cell centres on a lattice aligned to multiples of `cellSize` from the mesh bounds, inside by the same point test as the colliders, so a mesh that is not closed is the collider's error; one palette index (1) unless a later item maps mesh materials to indices; parallel over cells and deterministic (each cell independent).

## 3. The object: `<object3D primitive="voxels" voxels cellSize palette surface>`
`voxels` (IDREF to a `voxelAsset`), `cellSize` (scene units a cell, default the asset's `cellSize` or the grid's, else 1), `palette` (either `file`, the default when the file has colours, or the IDREFS of materials by index: index i uses the i-th, at most 255), `surface` (`blocks`, the only value now: every exposed face a quad; `smooth` is a later value). A material for each index: `palette[i]`, else the object's `material`, else the file's colour; an index with none of these is an error that names it. Position and scale as every object3D; the origin of the cells is the corner of the bounding box of the occupied cells, at the object's origin. Excluded with it: `mesh`, `volume`, `terrain`, `map`, `text`, `path`, a `medium` child. Names agreed from the physics side and used as given: `rigidBody@shape="voxels"`, `@density` (required, `mass` with it an error), `@maxFragments` (64), `@fragmentMinCells`, `@fragmentOverflow=error|dust`, CRT5 with `voxels`, `fracture@partition`; `mantle`, `bulking` and `repose` refused on an owner of voxels. Meshing reads the Occupancy by revision and changed bricks.

## 4. Rules (version 1.3, Schematron and Rust, corpus fixtures for each)
VOX1 `voxelAsset` needs version 1.3. VOX2 exactly one of `src` and `fromMesh`; `format` and `model` only with `src` (`model` only with `vox`); `cellSize` required with `fromMesh` and forbidden with `src`. VOX3 `fromMesh` names a `mesh` asset. VOX4 `primitive="voxels"` requires `voxels` naming a `voxelAsset`, and `voxels`, `cellSize`, `palette` and `surface` belong to that primitive. VOX5 `palette` is `file` alone or at most 255 distinct materials. VOX6 the exclusions above. VOX7 `maxCells` and `maxMemoryMiB` within their limits, `cellSize` positive. Run time (errors, not rules): file unreadable, malformed, `sha256` different, over the limits, an index with no material, a model out of range, an open mesh.

## 5. Oracles (each fails first)
(a) `.vox` fixtures written by a script that shares no code with the importer (`tools/make_vox.py`, Python `struct`): one model of 3 x 4 x 5 with known cells and palette; two models with a scene graph (translation, all 24 rotation bytes tested against a table computed independently); a MATL; a file with no RGBA; v150 and v200 headers; truncated and corrupt files (every one an error, none a panic, in a fuzz loop over byte flips and cut-offs): cells, palette entries and placed positions equal to the script's, 100 %. (b) A real MagicaVoxel file, if someone brings one (a small public-domain model of a few KB): same checks against the independent decoder; without it the offset-by-one of the palette, the centre of a model under the scene graph and the rotation byte are the three facts that stay unproved against the program that writes the format, and the SREP says so. (c) `srvol` round trip: Occupancy to srvol to Occupancy equal, revision equal. (d) `fromMesh`: a box gives exactly the cells whose centres are inside (an analytic count), a sphere the lattice points inside it counted by brute force, the volume `cells x cellSize^3` within half a surface layer of the mesh's, and every cell centre agrees with `Mesh::contains`; an open mesh is an error. (e) Determinism: any thread count, any order, a fresh load, the same Occupancy revision. (f) Corpus: valid and invalid documents for VOX1 to VOX7 with the independent oracle in agreement.

## 6. Risks and cost
The three unproved facts above; the default palette; the scene graph beyond frame 0 (animation) and layers are ignored and said; palettes of more than 255 entries (an `srvol` label above 255 is an error until the Occupancy has a wider index, which I ask Netuno to decide: u8 now); a model of 256^3 full is 16.7 million cells (16.7 MB of indices, 4 bytes a cell as an `srvol` grid) and `fromMesh` at a fine `cellSize` costs one oriented point query per lattice point in the box (a few seconds at 256^3, parallel), hence `maxCells` and the box check before the work. Size of the work: parser and fixtures about 2 days, `srvol` and `fromMesh` 1 day, schema, rules and corpus 1 day, SREP 0.5 day.
